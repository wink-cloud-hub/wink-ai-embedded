### 0.1 场景文档模板（每个子场景必须写齐）

| 字段 | 含义 |
|------|------|

| **保障方案** | A 规约 / B 引擎建模 / C 观测门禁 / 真机兜底；关键实现要点 |

#### 验收预言（Oracle）标准词汇汇编

| 标准词汇 | 约定含义 | 典型断言机制 |
|----------|----------|--------------|
| **Fail-Fast / Fail-Loud** | 编译期或内核初始化期直接阻断并明确报错 | `-DWINK_STRICT_NONBLOCKING=1` 编译失败、JSON 门禁卡死 |
| **Fault** | 运行时触发 Wasm/Host 内核故障隔离区并捕获上下文 | 堆配额 OOM (`-13`)、软 WDT 超时、影子内存 TSan 并发断言 |
| **Bit-Identical / Golden Trace** | 运行轨迹或计算输出与参考数据 100% 逐比特/逐微秒一致 | 同源状态机迁移 Trace 比对、固定 PRNG 丢包/去抖算法输出 |
| **Tolerance Band** | 允许在预设的物理/算法公差带（如 $\pm 2\%$）内验收 | RC 低通滤波物理拟合、传感器退化拟合曲线比对 |
| **真机 / HIL 独占** | 仿真侧标记为不可测，必须交由真机或 HIL 自动化测试套件兜底 | 20kHz 硬实时 ISR、SPICE 电气特性、多核物理缓存一致性 |

可测性标记（✅/🟡/❌/🚫）**只写在 08**，本规范只描述机制与方案。

### 0.2 解法类型与三道防线架构映射（与 08 共用词汇）

每个子场景的「保障方案」由以下三道防线及仿真底层建模协同构成：

| 架构层次 / 防线 | 对应解法类型 | 核心职责 | 典型手段 (WinkOS 工具链与内核机制) |
|-----------------|:---:|----------|-----------------------------------|
| **第一道防线：静态阻断** | **A. 约束写法** | 编译期或 IDE 毫秒级阻断危险代码写法，防止非法 API 或非同源代码泄露 | `wink-tools/tools/lint` 规则库、`-DWINK_STRICT_NONBLOCKING=1` 隐藏阻塞符号、`wink-app.json` 静态引脚冲突门禁 |
| **仿真核心底座** | **B. 引擎建模** | 在 Wasm/Host 内核中逼真复刻物理时间、总线传输与调度行为 | `s_virtual_us` 虚拟微秒时钟 SSOT、零 Yield 引脚事件队列、确定性混沌调度器 (PRNG)、DAL 100% 同源驱动 |
| **第二道防线：动态防护** | **C. 观测门禁** | 运行时捕获并发、溢出、耗尽、超时等动态逻辑异常并隔离 | 静态堆配额 Fault (`-13`)、影子内存 (TSan) 竞态断言、软 WDT 超时、ASan / UBSan 消毒器 |
| **第三道防线：真机兜底** | **真机 / HIL** | 承接仿真刻意不保的物理/硬实时/微架构特性，做最终交付验证 | Tier 3 HIL 自动化板卡测试流水线、20kHz 硬实时 ISR、SPICE 电气仿真、多核 Cache 抽样 |

### 0.4 A～F 完备后的生产口径与残余不一致

目录 [README](./README.md) 将仿真拆为正交轴 **A～F**（外设物理源 / 时间基 / 定时器 / 中断 / 调度并发 / 故障观测）。本小节规定：**轴建设目标与「虚实恒等」不可混为一谈**（对齐 [ADR-0003](../../../decisions/unisim/0003-simulation-fidelity-boundary.md)）。产品可读摘要亦见 README「A～F 完备后的产品口径」。

#### 生产口径定义

| 主张 | 是否为 A～F 完备后的目标 |
|---|---|
| 仿真作为发版前的**高置信行为级预检**（CI、低代码主路径尽早抓逻辑/协议/资源类逃逸） | **是** — 「生产可用的仿真预检」 |
| 仿真输出可**单独替代**真机 / HIL 作为放行依据 | **否** |
| 仿真与真机在任意场景 **bit / μs / 抢占序恒等** | **否** — 永不作为产品承诺 |

#### 完备后仍必然存在的不一致（模型上限）

| 来源 | 说明 |
|---|---|
| 电气 / 模拟 | ADC 量化、阻抗、电源、晶振漂移等非目标（多属 C11 🚫） |
| 中断模型上限 | 协作式 IRQ ≠ NVIC 抢占嵌套（C4 类不可用仿真证明无逃逸） |
| 定时器 / 快环上限 | 软步进 / 虚拟时钟 ≠ 芯片硬 ISR、PWM–ADC 硬件触发（C10） |
| 多核 / 微架构 | 单虚拟核；cache、DMA 争用、silicon errata → 真机 |
| 宿主环境 | Worker、Asyncify 挂起点改变墙钟观感；逻辑时序靠虚拟时钟，不靠墙钟对齐 |

#### 完备后应显著收敛的不一致

- 轴 A + 同源铁律：换算 / 超时 / 协议打包 / 错误恢复在仿真中真实执行。
- 轴 B：去抖、超时、周期任务在 `s_virtual_us` 下可复现。
- 轴 C/F（门禁子集）：引脚与定时器资源冲突、非法阻塞、配额/Fault Fail-Loud。
- 轴 E（协作子集）：饿死、软 WDT、部分共享状态问题更早暴露。
- 轴 F + [08](./08-simulation-consistency-checklist.md)：不可验场景显式 🚫，避免「仿真绿灯 = 真机安全」。

#### 管理原则

残余仿真↔真机差异必须 **分类管理**：

1. 查 [08](./08-simulation-consistency-checklist.md) 场景状态；
2. 🚫 / 真机独占项进入 HIL 或板级门禁；
3. 对外与对内评审统一使用 ADR-0003「行为级高保真」措辞，禁止「落实多轴后即可免上板」类表述。

## 1. 仿真一致性底层原理概述

### 1.1 核心基线：虚拟微秒时钟 SSOT (Virtual-Time Clock)

WinkOS 仿真内核放弃直接依赖宿主机墙钟（Wall-clock），全面采用单调递增的虚拟微秒时钟 `s_virtual_us` 作为唯一时钟 SSOT（[ADR-0009](../../../decisions/unisim/0009-physical-behavior-simulation-fault-injection.md)、[06](./06-physical-degradation-engine.md)）：

* **零耗时无缝跳跃 (Fast-Forwarding)**：HEADLESS 下当所有 Fiber 处于 `sleep`/等待事件时，`pal_sim_scheduler_run` 将 `s_virtual_us` 快进到最近 `next_wakeup_us`，使长时序测试可在毫秒级跑完。
* **物理逻辑绑定**：去抖（`wink_phys_debounce_step`）、RC 低通（`wink_phys_rc_lowpass`）、软定时器均锚定 `s_virtual_us`，保证跨宿主机确定性复现。
* **SSOT 红线**：`pal_delay_ms/us` **禁止**主动步进时钟；写入入口为 `pal_wasm_advance_virtual_clock`（及 HEADLESS 内部经单一 Gate 的合法第二调用者，见 [ADR-0042](../../../decisions/unisim/0042-sim-execution-modes.md)）。双重步进是 C14 级逃逸源。

### 1.2 控制域与物理域解耦的联合仿真 (Co-Simulation)

```
┌────────────────────────────────────────────────────────┐
│             应用控制域 (App Control Domain)            │  ◄── 100% C 业务代码 (同源编译)
└───────────────────────────┬────────────────────────────┘
                            ▼
┌────────────────────────────────────────────────────────┐
│             平台仿真底座 (Platform Sim OS)             │  ◄── 领域无关
│   (时钟、调度、虚拟引脚、中断 Poll、通信总线)              │
└───────────────────────────┬────────────────────────────┘
                            ▲ (管脚/总线双向交换)
                            ▼
┌────────────────────────────────────────────────────────┐
│           外部环境/器件模型 (Simulation Plugins)       │  ◄── 物理算法插件
│    - 运动学/动力学、传感器退化状态机等                     │
└────────────────────────────────────────────────────────┘
```

#### 1.2.1 平台数据面
* **导出**：`pal_wasm_get_gpio_output`、`pal_wasm_get_pwm_duty_percent` 等。
* **注入**：`pal_wasm_set_gpio_input`、`pal_wasm_set_ultrasonic_distance` 等。
* 内核保持 **零具体业务物理痕迹**；小车等算法只存在于插件。

#### 1.2.2 联合仿真步进契约（Step-Lock Pipe）
1. 插件读取控制信号（PWM 等）；
2. 按 $\Delta t$ 更新物理状态并计算传感器量；
3. 经注入 API 写回底座。  
锁步破坏（plant 与 OS 时钟不同步）见 **C14**。

### 1.3 零 Yield 同步事件驱动快进

天真的引脚时序环回若在 `pal_gpio_pulse_in` 上 Asyncify Yield，会因 Unwind/Rewind 拖慢 10～50×。机制：

1. **Pin Event Queue**：C 侧维护未来引脚变化时间链表。
2. **Zero-Yield Callback**：Trig 跃变时同步回调插件，插件把 Echo 边沿时间戳写入队列。
3. **同步时钟跃进**：`pulse_in` 直接累加 `s_virtual_us` 并返回脉宽，**Asyncify 次数为 0**。

性能正确，但跳跃会漏边沿/半窗 debounce——契约与逃逸见 **C14**。

## 2. 场景化一致性保障（C1～C25：大类 + 子场景）

> 可测性状态统一见 [08](./08-simulation-consistency-checklist.md)。下文只写问题、方案、预言与边界。

---

### C1 — 业务因果与状态机逻辑

**大类目标**：App/BAL 状态机、传感器语义、执行器命令、故障/超时路径在仿真与真机上因果一致。

#### C1.1 同源 App/BAL 状态迁移
* **问题**：仿真跑另一套「简化逻辑」导致状态机「绿」但真机分支不同。
* **真机 vs 仿真**：真机与仿真必须共用同一 C 源（[ADR-0002](../../../decisions/unisim/0002-dual-target-compilation.md)）。
* **保障方案**：**B** 双 Target 同源编译；禁止 App 层 `#ifdef SIMULATION` 改业务分支。
* **验收预言**：同一输入序列下状态迁移轨迹（或 golden trace）bit-identical / 语义等价。
* **边界**：DAL/PAL 旁路导致的细节差异归 C1.2/C7，不记在本子项「已完全同源」。

#### C1.2 DAL Bypass / `#ifdef SIMULATION` 收窄
* **问题**：整驱动被 JS 替换 → CRC/超时/重试从未在仿真跑过（ADR-0003 决策 2）。
* **真机 vs 仿真**：真机跑完整驱动；仿真若 Bypass 整层则协议路径逃逸。
* **保障方案**：**A+B** 仅替换物理量来源；[ADR-0040](../../../decisions/unisim/0040-arduino-semantic-sim-json-gate.md) JSON 门禁 Fail-Loud；持续审计残留 Bypass。
* **验收预言**：未在 `wink-app.json` 声明的语义 Bypass 编译/运行期失败；声明器件的协议层仍走 C 路径。
* **边界**：物理量本身仍来自插件/注入，不宣称电气等价。

#### C1.3 故障 / 超时 / 断线异常路径
* **问题**：只测 happy path，真机断线/超时状态机未覆盖。
* **真机 vs 仿真**：真机偶发；仿真可用确定性故障注入复现。
* **保障方案**：**B** 退化引擎 / 总线 `drop_permil` / 超时注入（[06](./06-physical-degradation-engine.md)）。
* **验收预言**：注入断线/超时后进入约定故障态，且恢复序列可复现。
* **边界**：电气层断线阻抗变化归 C11 🚫。

#### C1.4 幂等恢复与重试风暴
* **问题**：错误恢复路径重复入队/重复下发执行器命令。
* **真机 vs 仿真**：协作调度下时序固定，可能掩盖「重试窗口重叠」。
* **保障方案**：**B+C** 故障注入拉长 ACK 超时；观测命令计数/序列号单调性。
* **验收预言**：单次故障注入下执行器命令次数 ≤ 规约上限；无未界定双发。
* **边界**：网络层 exactly-once 不在本 OS 范围。

---

### C2 — 虚拟微秒逻辑时序（单任务 / 单中断友好）

**大类目标**：在单任务或「中断不与计算重叠」场景下，逻辑时间（sleep、脉宽、去抖、采样周期）确定性一致。多消费者时钟与快进副作用见 **C14/C21**。

#### C2.1 `sleep` / 定时唤醒快进
* **问题**：依赖墙钟导致后台 Tab 节流、CI 抖动。
* **真机 vs 仿真**：真机墙钟近似；仿真必须虚拟时间。
* **保障方案**：**B** `s_virtual_us` + 调度器快进到 `next_wakeup_us`。
* **验收预言**：同 seed/同注册序下唤醒时刻序列可复现；墙钟耗时 ≪ 虚拟跨度。
* **边界**：不默认模拟晶振 ±50ppm（需退化引擎主动注入）。

#### C2.2 脉宽测量零 Yield 环回
* **问题**：`pulse_in` Yield 导致性能崩溃或时序漂移。
* **真机 vs 仿真**：真机忙等/输入捕获；仿真用 Pin Event Queue 同步结算（§1.3）。
* **保障方案**：**B** 同步事件驱动快进。
* **验收预言**：已知距离/脉宽映射下返回值误差在契约容差内；过程中 Asyncify 挂起次数为 0（HEADLESS 路径）。
* **边界**：快进跳过中间边沿见 C14.2。

#### C2.3 去抖 / RC 低通锚定虚拟时钟
* **问题**：滤波窗口跟墙钟走 → 不同机器结果不同。
* **真机 vs 仿真**：真机有模拟噪声；仿真算法必须绑 `s_virtual_us`。
* **保障方案**：**B** `wink_phys_*` 统一读虚拟时钟（[06](./06-physical-degradation-engine.md)）。
* **验收预言**：固定输入边沿序列 + 固定参数 → 滤波输出 golden 向量一致。
* **边界**：噪声幅值是注入参数，非电路级噪声。

#### C2.4 单中断友好采样周期
* **问题**：周期任务「以为」按固定 ms 跑，实际被调度抖动打乱。
* **真机 vs 仿真**：真机抢占抖动大；仿真协作式更稳，可能**过于理想**。
* **保障方案**：**B** 虚拟周期断言；可选 **C** 注入受控抖动（退化引擎）。
* **验收预言**：无注入时周期误差为 0（虚拟时间）；注入抖动后业务仍满足规约或显式失败。
* **边界**：硬实时周期归 C10。

### C3 — 共享状态竞态（Task↔Task / Task↔ISR）

**大类目标**：无锁共享、多字段撕裂、Task/ISR 交叉访问能被激发并检出。

#### C3.1 无锁共享读写（Task↔Task）
* **问题**：两任务无锁读写同一变量；协作调度下固定交错「永远不错」。
* **真机 vs 仿真**：真机抢占/双核易爆；仿真 RR 掩盖。
* **保障方案**：**B** 确定性混沌调度（PRNG + `fairness_bound`，[ADR-0042](../../../decisions/unisim/0042-sim-execution-modes.md)）；**C** 影子内存 TSan。
* **验收预言**：混沌模式下已知竞态用例稳定 Fault；加临界区后 Fault 消失。
* **边界**：非真实双核重叠写（见 C9）。

#### C3.2 Task↔ISR 无锁交叉
* **问题**：Task 读多字节状态时被 ISR 半更新。
* **真机 vs 仿真**：真机任意指令间刺入；仿真仅在 yield/poll 点插 ISR。
* **保障方案**：**B** 多调度点插 ISR；**C** TSan 标记 ISR 上下文访问。
* **验收预言**：故意无保护的多字节共享在混沌+ISR 注入下检出。
* **边界**：指令间任意刺入需 Phase 4 加深，仍非周期精确。

#### C3.3 多字段结构体撕裂
* **问题**：`{x,y}` 或「长度+指针」只更新一半被读者看见。
* **真机 vs 仿真**：同 C3.1/C3.2，结构体更易漏。
* **保障方案**：**C** 影子内存按字段/按对象版本号；**A** 规约要求 seqlock/临界区。
* **验收预言**：半更新用例 Fault；完整临界区或 seqlock 后通过。
* **边界**：不保证检测所有 lock-free ABA。

#### C3.4 发布-订阅顺序假设
* **问题**：写 flag 前未写完 payload（缺内存屏障/发布序）。
* **真机 vs 仿真**：单核 Wasm 弱化乱序可见性差异；真机多核/编译器重排更狠。
* **保障方案**：**A** 禁止裸 flag 协议；**C** TSan/审阅；真机抽样。
* **验收预言**：lint/审阅门禁拦截裸 flag 模式；混沌下尽量激发。
* **边界**：完整 memory model 仿真不在日间轨（→ C12/C24）。

### C4 — 临界区与中断抢占 / 嵌套

#### C4.1 临界区门禁（enter/exit）
* **问题**：忘记 `critical_exit`、嵌套计数错误、在临界区内 sleep。
* **真机 vs 仿真**：真机可能硬锁或随机崩；仿真可断言。
* **保障方案**：**B+C** `pal_os_critical_enter/exit` 状态机断言；临界区内禁 ISR 派发。
* **验收预言**：未配对 exit → Fault；临界区内 pending IRQ 延迟到 exit 后。
* **边界**：不等价于关硬件全局中断的全部副作用。

#### C4.2 调度点 ISR 投递（Poll 模型）
* **问题**：误以为随时可抢占；实际仅 tick/yield 边界 poll（[01](./01-wasm-sandbox-lifecycle.md)）。
* **真机 vs 仿真**：真机硬件刺入；仿真 Poll。
* **保障方案**：**B** 文档化 Poll 语义；Phase 4 增多插入点逼近。
* **验收预言**：在已知 yield 点注册边沿 → ISR 必在下一 poll 窗口执行；无 yield 的纯计算窗口内不执行（基线）。
* **边界**：任意指令间刺入 ❌（产品需知）。

#### C4.3 优先级嵌套
* **问题**：高优先级 ISR 打断低优先级 ISR/Task。
* **真机 vs 仿真**：ESP-IDF/FreeRTOS 支持；仿真基线单级。
* **保障方案**：**B** Phase 4 先做单级抢占 + 临界区；嵌套为后续增强；真机兜底。
* **验收预言**：单级：临界区外可插；嵌套用例在未实现前标记为真机。
* **边界**：完整嵌套优先级不承诺日间轨。

#### C4.4 FromISR / 非 ISR-safe API 误用
* **问题**：在 ISR 里调会阻塞或取锁的 API。
* **真机 vs 仿真**：真机偶发死锁/断言；仿真可能「碰巧能跑」。
* **保障方案**：**A** lint/API 属性（ISR-safe 白名单）；**C** ISR 上下文调用非安全 API → Fault。
* **验收预言**：用例在 ISR 调 `mutex_lock` 必 Fault。
* **边界**：第三方闭源回调需人工标注。

#### C4.5 Pending 中断队列溢出
* **问题**：边沿风暴超过 `PAL_WASM_INTERRUPT_QUEUE_SIZE`（默认 16）→ 丢中断。
* **真机 vs 仿真**：真机可能硬件挂起 pending；仿真队列满则丢或需定义策略。
* **保障方案**：**C** 队列满 Fail-Loud（计数/Fault）；**B** 可配置深度；文档诚实。
* **验收预言**：注入 > 容量边沿 → 可观测溢出计数或 Fault，禁止静默丢且假装已处理。
* **边界**：不模拟芯片特定中断控制器全状态。

### C5 — 阻塞 / 饿死 / 看门狗

#### C5.1 STRICT_NONBLOCKING 编译期隐藏阻塞 API
* **问题**：App 误用阻塞读导致真机 WDT。
* **真机 vs 仿真**：仿真默认开启严格模式（[ADR-0025](../../../decisions/core/0025-app-blocking-api-honesty-pragma-convention.md)）。
* **保障方案**：**A** `-DWINK_STRICT_NONBLOCKING=1`；阻塞符号隐藏 → 链接失败。
* **验收预言**：App 调用 `WINK_BLOCKING` API 在仿真构建失败。
* **边界**：Bringup/selftest 在非严格配置隔离。

#### C5.2 软 WDT（虚拟时间未喂狗）
* **问题**：任务死循环不喂狗。
* **真机 vs 仿真**：真机硬件 WDT 复位；仿真用虚拟时间软 WDT。
* **保障方案**：**B+C** 超过 N 虚拟 ms 未喂狗 → Fault 隔离。
* **验收预言**：停喂狗用例在阈值虚拟时间内 Fault。
* **边界**：不反映宿主机 CPU 耗尽导致的**物理** WDT（见调度 WCET 墙钟兜底，[07](./07-scheduler-model.md)）。

#### C5.3 就绪任务饿死
* **问题**：高优先级/从不 yield 的任务饿死低优先级。
* **真机 vs 仿真**：真机有时间片；仿真协作式更易饿死或完全相反（RR 更公平）。
* **保障方案**：**C** 就绪但长期未运行计数告警；**B** 混沌公平边界。
* **验收预言**：构造饿死用例触发告警/Fault。
* **边界**：与 FreeRTOS 优先级抢占语义不完全等价（见 C16）。

#### C5.4 动态间接阻塞
* **问题**：经函数指针/回调间接调用阻塞路径，静态规约漏网。
* **真机 vs 仿真**：同危险。
* **保障方案**：**A** 尽量静态可见；**C** 运行时「阻塞点」探测（在阻塞 API 入口检查调用上下文）。
* **验收预言**：间接调用阻塞 API 仍被运行时门禁抓住（在可探测路径上）。
* **边界**：纯汇编/极端混淆不保证。

#### C5.5 优先级反转
* **问题**：低优先级持锁，高优先级忙等/阻塞，中优先级抢跑。
* **真机 vs 仿真**：需优先级继承/天花板；仿真基线可能无。
* **保障方案**：**B** 文档声明是否实现继承；**C** 检测「高优先级阻塞在低优先级持有的锁上超过阈值」；真机验证。
* **验收预言**：经典反转用例在声明支持继承时通过，否则显式 🟡/真机。
* **边界**：完整继承协议可分阶段。

### C6 — 栈 / 堆 / 内存安全

#### C6.1 静态堆配额耗尽
* **问题**：仿真堆远大于真机 SRAM，隐藏 OOM 路径。
* **真机 vs 仿真**：真机早 OOM；仿真需配额（[ADR-0045](../../../decisions/unisim/0045-simulation-memory-quota-and-fault-policy.md)）。
* **保障方案**：**B** `sim_heap[WINK_SIM_HEAP_QUOTA_BYTES]`；耗尽返回 NULL → `WINK_ERR_NO_MEM`。
* **验收预言**：配额耗尽用例走 Fault/错误处理，与真机错误码语义对齐。
* **边界**：碎片形态与真机分配器不完全一致。

#### C6.2 堆碎片化
* **问题**：反复 alloc/free 后「总量够但分配失败」。
* **真机 vs 仿真**：分配器不同则碎片图不同。
* **保障方案**：**B** 可选碎片压力测试模式；**C** 分配失败注入。
* **验收预言**：压力模式可触发 NO_MEM；业务有降级路径。
* **边界**：不宣称与 ESP-IDF heap 碎片几何相同。

#### C6.3 ASan / UBSan（UAF、越界、未对齐、溢出）
* **问题**：野指针、UAF、越界在无消毒器时静默。
* **真机 vs 仿真**：真机表现随机；Host 测可开 Sanitizer。
* **保障方案**：**C** ASan + UBSan 接入 CI/Host。
* **验收预言**：已知坏用例被 Sanitizer 拦截。
* **边界**：Wasm 日间轨不一定全能开 ASan。

#### C6.4 App 禁裸 malloc
* **问题**：应用层直接 `malloc` 破坏资源模型。
* **保障方案**：**A** `NO-MALLOC-APP` lint。
* **验收预言**：违规调用 lint 失败。
* **边界**：平台层分配器内部除外。

#### C6.5 Per-task 栈溢出
* **问题**：任务栈过小；Wasm 单栈/Fiber 与 FreeRTOS 多栈模型不同。
* **真机 vs 仿真**：真机栈金丝雀；Wasm 可能不同布局。
* **保障方案**：**C** Fiber/栈水位或 `STACK_OVERFLOW_CHECK`；**B** 尽量 per-task 栈会计。
* **验收预言**：故意深递归/大帧用例触发溢出检测。
* **边界**：与 Xtensa 栈红区逐字节对齐 ❌。

#### C6.6 缓冲区在 DMA/异步传输中被复用
* **问题**：传输未完成就改 buffer（与 C19 交叠）。
* **保障方案**：见 **C19**；本项强调内存所有权。
* **验收预言**：传输窗口内写 buffer → Fault 或数据损坏被测出。
* **边界**：依赖 C8 异步窗口先存在。

### C7 — 总线协议帧 / CRC / 错误恢复

#### C7.1 同源协议帧与 CRC
* **问题**：Bypass 掉 CRC → 真机坏帧处理未测。
* **保障方案**：**B** DAL 同源；坏 CRC 注入。
* **验收预言**：坏 CRC 帧走错误恢复，不进入业务成功态。
* **边界**：电气误码形态归 C11/C18。

#### C7.2 ACK 超时与重试
* **问题**：超时时间、重试次数与真机不一致。
* **保障方案**：**B** 虚拟时间超时；丢包 `drop_permil`。
* **验收预言**：固定丢包种子下重试次数/最终错误码可复现。
* **边界**：线缆延迟频谱不建模。

#### C7.3 JSON 语义仿真门禁
* **问题**：未声明器件却走语义捷径。
* **保障方案**：**A** [ADR-0040](../../../decisions/unisim/0040-arduino-semantic-sim-json-gate.md)。
* **验收预言**：未配置外设 Fail-Loud。
* **边界**：门禁只管「是否允许 Bypass」，不管 Bypass 内容是否电气正确。

#### C7.4 残留 Bypass 清零审计
* **问题**：个别驱动遗留整层 `#ifdef SIMULATION`。
* **保障方案**：**A+C** 静态扫描 + CI 审计列表。
* **验收预言**：审计列表为空或每项有豁免 ADR。
* **边界**：物理量钩子层的 `#ifdef` 允许存在。

### C8 — DMA / 总线异步传输窗口

#### C8.1 粗粒度传输耗时挂起
* **问题**：`pal_i2c_transfer` 0us 返回，掩盖「传输中并发改缓冲」。
* **真机 vs 仿真**：真机 DMA 期间 CPU 可跑别的任务。
* **保障方案**：**B** 按字节率计算虚拟耗时，挂起 Task，到期完成 IRQ 唤醒。
* **验收预言**：传输窗口内另一 Task 写共享缓冲可被竞态测出（配合 C3/C19）。
* **边界**：非 cycle 精确总线时序。

#### C8.2 完成中断与任务唤醒序
* **问题**：完成回调与等待 Task 的唤醒顺序假设错误。
* **保障方案**：**B** 明确「先置完成标志/入队，再 resume」；混沌打乱同优先级。
* **验收预言**：用例验证官方序；错误序在混沌下失败。
* **边界**：与芯片 DMA IRQ 优先级细项可能仍有差。

#### C8.3 同步 API 残留
* **问题**：部分 PAL 仍同步完成 → C8 空洞。
* **保障方案**：**B** 总线 API 清单迁移；**A** 标注 sync-only 符号。
* **验收预言**：目标总线均有异步模型或显式「sync-only」标签。
* **边界**：过渡期允许标注豁免。

### C9 — 多核 SMP 真实并发

#### C9.1 单虚拟核产品边界
* **问题**：用户期望浏览器内双核。
* **保障方案**：遵循 [ADR-0014](../../../decisions/unisim/0014-sim-single-virtual-core.md)——**刻意不保**真双核；对外口径清晰。
* **验收预言**：文档/08 标记 🚫/❌；无「双核已仿真」宣传。
* **边界**：真机兜底。

#### C9.2 混沌交错近似多核竞态
* **问题**：单核仍可能通过高频插队逼近部分竞态。
* **保障方案**：**B** Phase 4 混沌；真机双核测试补强。
* **验收预言**：已知单核可激发竞态在混沌下检出；双核专用用例进真机套件。
* **边界**：缓存一致性、跨核中断路由不建模（C24）。

### C10 — 快环 ISR（FOC / 硬定时器）

#### C10.1 虚拟时间软步进近似
* **问题**：20kHz 硬 ISR 在 Wasm 不可得。
* **保障方案**：**B** [ADR-0047](../../../decisions/core/0047-foc-isr-layering-and-pal-hwtimer.md) 软步进；plant 方程在 `wink_sim_physical`；禁墙钟/rand。
* **验收预言**：固定虚拟步进下控制状态可复现；与 golden 轨迹比对。
* **边界**：不保真 50µs 硬实时。

#### C10.2 PWM–ADC 硬件同步降级
* **问题**：真机硬件触发采样；仿真软步进相位可能偏。
* **保障方案**：**B** 文档降级；逻辑正确性可测，相位误差真机/HIL。
* **验收预言**：相位敏感用例进 HIL 清单；仿真只验控制律。
* **边界**：🚫 周期精确同步。

#### C10.3 DI / ISR 分层边界
* **问题**：业务逻辑塞进快环导致不可仿真、不可测。
* **保障方案**：**A** ADR-0047 分层；lint 限制快环调用面。
* **验收预言**：快环仅允许白名单 PAL；违规 lint 失败。
* **边界**：白名单随产品演进。

### C11 — 电气 / 模拟电路特性

#### C11.1 SPICE / 电源完整性
* **保障方案**：🚫 [ADR-0003](../../../decisions/unisim/0003-simulation-fidelity-boundary.md)；真机/专用工具。
* **验收预言**：对外承诺不含本项。
* **边界**：刻意不保。

#### C11.2 退化引擎查表近似
* **问题**：完全理想传感器误导调参。
* **保障方案**：**B** [06](./06-physical-degradation-engine.md) 抖动/噪声/预热/丢包。
* **验收预言**：注入参数改变读数分布；理想模式 `{0}` 可回归。
* **边界**：非 SPICE；参数是经验表。

#### C11.3 ADC 量化 / 参考电压 / 管脚电容
* **保障方案**：🚫 或极粗量化档位可选；默认不保。
* **验收预言**：若提供粗量化，有单元测试；否则 08 标 🚫。
* **边界**：认证级模拟精度真机。

### C12 — CPU / ABI 指令级一致性

#### C12.1 日间极速轨道（Wasm/Host Native）
* **保障方案**：**B** 快速迭代；接受 ABI 与真机可能差。
* **验收预言**：功能测试秒级反馈。
* **边界**：非指令级。

#### C12.2 夜间 RISC-V 32 / 真机二进制双轨
* **问题**：padding、对齐、调用约定、枚举宽度导致「仿真过、上板崩」。
* **保障方案**：**C** Phase 5 解释器或真机 `.bin` 对照。
* **验收预言**：故意 padding 敏感用例夜间轨失败或报警。
* **边界**：速度慢；非日间必跑。

#### C12.3 结构体打包 / 枚举 / 位域
* **保障方案**：**A** 打包规约 + static assert；**C** 双轨。
* **验收预言**：`_Static_assert(sizeof...)`；跨 target 大小一致或显式分支。
* **边界**：位域布局仍编译器相关，慎用。

#### C12.4 端序与未对齐访问
* **保障方案**：**C** UBSan；协议层显式序列化。
* **验收预言**：未对齐用例 Host UBSan 拦截；线上协议有序列化测试。
* **边界**：Wasm 与 Xtensa 对未对齐容忍度不同。

### C13 — 生命周期 / 复位 / 冷热启动

**大类目标**：启动、再初始化、热重启后的状态与真机「上电/复位」语义对齐，避免仿真残留污染。

#### C13.1 冷启动：BSS / 静态初值 / 外设默认电平
* **问题**：仿真热复用模块导致静态变量/GPIO 默认态不像上电。
* **真机 vs 仿真**：真机上电为硬件默认；Wasm 二次 INIT 可能残留。
* **保障方案**：**B** `INIT` 路径强制 `pal_wasm_reset_physical` + 调度器/堆/PRNG 复位；文档定义冷启动清单。
* **验收预言**：两次 INIT 之间状态与冷启动向量一致（无业务残留）。
* **边界**：芯片特定 strap 脚电平可不全仿真。

#### C13.2 热重启 / 软复位原因
* **问题**：依赖 `esp_reset_reason` 的分支在仿真恒为某值。
* **保障方案**：**B** 可注入复位原因；**A** 未实现则文档标 🟡。
* **验收预言**：注入 BROWN-OUT/WATCHDOG 等枚举后走对应恢复路径。
* **边界**：真实供电掉落波形 🚫。

#### C13.3 外设 deinit / 再 init
* **问题**：二次 init 未 deinit → 句柄泄漏、IRQ 重复注册。
* **保障方案**：**C** 重复注册断言；资源会计。
* **验收预言**：重复 init 用例 Fail-Loud 或幂等成功（与 API 契约一致）。
* **边界**：契约必须先写清「是否幂等」。

#### C13.4 任务/对象生命周期与 Zombie GC
* **问题**：`task_delete` 后仍触碰栈/队列（[07](./07-scheduler-model.md) ZOMBIE/TERMINATED）。
* **保障方案**：**B** 调度器 GC 语义；**C** UAF Sanitizer。
* **验收预言**：delete 后访问 → Fault/ASan。
* **边界**：与 FreeRTOS 删除异步细节可能有差，需对照表。

### C14 — 快进 / 联合仿真步进契约

**大类目标**：虚拟时间跳跃与 plant 锁步不破坏因果；禁止双重步进。

#### C14.1 时钟单一写入 / 禁止双重步进
* **问题**：`delay` 与 Worker 同时 advance → 时间撕裂。
* **保障方案**：**A+B** SSOT 红线（§1.1）；CI 断言写入入口唯一。
* **验收预言**：静态/运行时检测第二写入者 → Fail。
* **边界**：HEADLESS 内部 Gate 必须文档化为合法例外。

#### C14.2 快进跨越边沿 / 半窗 debounce
* **问题**：跳到 `next_wakeup` 时跳过应在中间发生的 GPIO 边沿或 debounce 半窗结算。
* **保障方案**：**B** 快进前先排空到期 pin events / phys step；或快进取「下一事件」全局最小时间。
* **验收预言**：中间应有边沿的用例在快进下仍触发；debounce 窗口不被错误缩短/拉长。
* **边界**：事件队列容量满时见 C4.5/C14.4。

#### C14.3 Plant↔OS 锁步漂移
* **问题**：JS plant 用墙钟或不同 Δt，与 `s_virtual_us` 脱节。
* **保障方案**：**B** Step-Lock：同一 `virtual_dt` 驱动 OS 与 plant；禁 plant 读 `Date.now`。
* **验收预言**：同种子轨迹可复现；故意墙钟 plant 被门禁拒绝或测试失败。
* **边界**：可视化插值允许，但**不得**回写控制决策。

#### C14.4 Pin Event Queue 溢出 / 丢失
* **问题**：同步回调写入过多未来边沿导致丢事件。
* **保障方案**：**C** 队列满 Fault；**B** 深度可配。
* **验收预言**：溢出可观测，不静默。
* **边界**：深度与真机硬件 FIFO 无关。

#### C14.5 观测与注入竞态
* **问题**：读 GPIO 输出同时 plant 写输入，无明确屏障。
* **保障方案**：**B** 规定 step 内「先读控制 → 算 plant → 再注入」序；测试固定该序。
* **验收预言**：破坏序的测试夹具应失败或被 API 禁止。
* **边界**：并行 Worker 多 plant 需额外屏障规约。

### C15 — Host↔Wasm 边界诚实性

**大类目标**：仿真底座自身不「骗人」；Asyncify/ABI/门禁错误 Fail-Loud。

#### C15.1 Asyncify 挂起契约
* **问题**：`sleep` 未返回 Promise / `__async` 写错 → 静默不睡或 rewind 死循环（[ADR-0019](../../../decisions/unisim/0019-wasm-imports-override-and-asyncify-syntax.md)、[01](./01-wasm-sandbox-lifecycle.md)）。
* **保障方案**：**A** js-library wrapper 规范；**C** 非法 Asyncify 状态断言。
* **验收预言**：错误覆盖用例在 CI 失败；正确路径可挂起恢复。
* **边界**：仅覆盖本仓约定的 import 集。

#### C15.2 中断 Push→Poll / 重入
* **问题**：旧 Push 模型在 sleeping 窗口重入崩溃；必须 Poll。
* **保障方案**：**B** 禁止导出 `_trigger_wasm_interrupt`；仅 pending 队列 + dispatch。
* **验收预言**：静态检查无 Push 导出；重入用例不崩。
* **边界**：Poll 延迟语义见 C4.2。

#### C15.3 bigint / 指针 ABI
* **问题**：`number` 截断 uint64 时钟；悬空指针传 JS。
* **保障方案**：**A** `-s WASM_BIGINT=1`；TS 全链路 `bigint`；指针生命周期规约。
* **验收预言**：大时钟值往返不丢；生命周期违规测试 Fail。
* **边界**：第三方 JS 插件需遵守同一契约。

#### C15.4 语义 Bypass 泄露
* **问题**：Workbench 或测试直接调语义捷径绕过门禁。
* **保障方案**：**A** ADR-0040；**C** 运行时探针。
* **验收预言**：未授权 Bypass 失败。
* **边界**：调试器手工内存写不在范围。

#### C15.5 Worker 隔离与主线程 starve
* **问题**：主线程跑 Wasm+Asyncify → timer starve / OOM。
* **保障方案**：**A** 必须 Worker（[01](./01-wasm-sandbox-lifecycle.md)）。
* **验收预言**：架构测试/文档门禁；禁止主线程加载路径。
* **边界**：Node 宿主另有约束说明。

### C16 — OS 同步原语语义对齐

**大类目标**：mutex/queue/ringbuf/timeout 与真机 OSAL 契约对齐，避免「返回值碰巧不同」。

#### C16.1 Mutex 锁 / 超时 / 递归
* **问题**：超时返回码、能否递归与 FreeRTOS 不一致。
* **保障方案**：**B** 语义对照表（[07](./07-scheduler-model.md)）；`timeout_fired` 行为单测。
* **验收预言**：对照表每行有测试；递归策略与文档一致（禁则或支持）。
* **边界**：优先级继承见 C5.5。

#### C16.2 Queue / Ringbuf 满与覆盖策略
* **问题**：满时阻塞 vs 丢最旧 vs 拒绝——仿真与真机不一致则丢数。
* **保障方案**：**B** API 契约写死；**C** 满/空计数观测。
* **验收预言**：满队列用例返回码/丢弃策略与契约一致。
* **边界**：零拷贝 DMA 队列另见 C19。

#### C16.3 阻塞等待与超时唤醒序
* **问题**：事件与超时同时到期的胜者未定义。
* **保障方案**：**B** 规定优先级（例如事件优先）；单测钉死。
* **验收预言**：同时到期用例结果稳定且符合契约。
* **边界**：真机若不同需在对照表注明「有意差」或改仿真。

#### C16.4 任务通知 / 事件组（若暴露）
* **问题**：bit 自动清除、等待多 bit 语义易错。
* **保障方案**：**B** 有则测；无则 **A** 不暴露或标实验 API。
* **验收预言**：每个暴露 API 有语义测试。
* **边界**：未暴露则 08 标 N/A。

#### C16.5 死锁检测
* **问题**：A 持锁等 B、B 持锁等 A。
* **保障方案**：**C** 可选等待图检测 / 超时；**A** 锁序规约。
* **验收预言**：经典死锁用例超时或 Fault。
* **边界**：不完全证明无死锁。

### C17 — 外设资源互斥 / 时基耦合

**大类目标**：合法 API、非法资源组合在仿真/codegen 阶段失败，而非上板才发现。

#### C17.1 引脚复用冲突
* **问题**：两器件声明同一 GPIO。
* **保障方案**：**A** codegen/板级 JSON 冲突检测；仿真注册时断言。
* **验收预言**：冲突配置 Fail-Loud。
* **边界**：动态运行时改脚需额外 API 契约。

#### C17.2 定时器 / PWM 通道独占
* **问题**：同一硬件定时器被 PWM 与输入捕获共用。
* **保障方案**：**A** 资源分配表；**C** 二次占用 Fault。
* **验收预言**：双占用用例失败。
* **边界**：芯片特定共享模式若合法需白名单。

#### C17.3 APB / 外设时钟变更副作用
* **问题**：改 CPU/APB 频率后 UART 波特率/PWM 频率暗变。
* **保障方案**：仿真 **B** 粗模型或 **🚫** 声明不保；真机测。
* **验收预言**：若建模，频率变更后波特率误差有断言；否则 08 标 🚫。
* **边界**：完整时钟树 🚫。

#### C17.4 PWM 占空比更新毛刺 / 相位连续性
* **问题**：更新 duty 造成一拍毛刺；仿真瞬时写寄存器无毛刺。
* **保障方案**：**B** 可选「下周期生效」模型；或文档 🟡。
* **验收预言**：若建模，更新对齐周期边界；否则标近似。
* **边界**：电气毛刺 🚫（C11）。

#### C17.5 共享总线所有权（多驱动争用）
* **问题**：两任务同时 `i2c_transfer` 无锁。
* **保障方案**：**A** 总线锁规约；**C** 重叠传输窗口检测 Fault。
* **验收预言**：无锁并发 transfer 被检出。
* **边界**：多主仲裁见 C18。

### C18 — 总线故障态机（超越 CRC/丢包）

#### C18.1 I2C NACK / clock stretch / 总线挂死
* **问题**：只测丢包，不测 NACK、拉死 SCL、recovery。
* **保障方案**：**B** 注入 NACK/stretch 超时；recovery 序列走同源驱动。
* **验收预言**：注入后错误码与恢复后成功可复现。
* **边界**：电气上升沿 🚫。

#### C18.2 UART framing / break / FIFO 溢出 / idle-line
* **问题**：坏帧、FIFO 满丢字节未测。
* **保障方案**：**B** 注入 framing 错误与 RX 溢出；**C** 溢出计数。
* **验收预言**：溢出后驱动进入约定错误/丢弃策略。
* **边界**：采样点相位 🚫。

#### C18.3 SPI 模式 / CS 时序 / 全双工
* **问题**：CPOL/CPHA 或 CS 早晚沿假设错误。
* **保障方案**：**B** 模式参数进模型；错误模式导致数据不匹配测试失败。
* **验收预言**：错误模式用例失败；正确模式 golden 通过。
* **边界**：板级飞线延迟 🚫。

#### C18.4 传输中止 / 半包恢复
* **问题**：abort 后状态机卡在半包。
* **保障方案**：**B** abort API + 驱动恢复；测试半包后续帧。
* **验收预言**：abort 后下一帧可成功或明确错误。
* **边界**：DMA abort 细节交叠 C19。

#### C18.5 多主仲裁（若产品需要）
* **保障方案**：多数产品 **🚫**；若需要则 **B** 简化仲裁胜者模型。
* **验收预言**：有需求才建；否则 08 标 🚫。
* **边界**：完整 I2C 仲裁时序真机。

---

### C19 — DMA / 缓冲生命周期

#### C19.1 半传输 / 双缓冲切换
* **问题**：只建模「全完成」，半缓冲回调逻辑未跑。
* **保障方案**：**B** 可选 half-complete 事件；双缓冲所有权切换断言。
* **验收预言**：半传输用例回调次数与缓冲索引正确。
* **边界**：粗粒度时间，非 beat 级。

#### C19.2 传输中缓冲区复用
* **问题**：DMA 进行中 cpu 写同一 buffer。
* **保障方案**：**C** 窗口内写检测（配合 C8）；**A** API 生命周期文档。
* **验收预言**：窗口内写 → Fault。
* **边界**：依赖异步窗口存在。

#### C19.3 Abort 后描述符 / 句柄残留
* **问题**：abort 后仍以为 DMA 跑着或重复 free。
* **保障方案**：**B** 状态机；**C** double-free/UAF Sanitizer。
* **验收预言**：abort 后再 start 成功；非法二次 abort 有明确错误码。
* **边界**：芯片描述符硬件格式不仿真。

#### C19.4 DMA 可访问内存区（与 C24 交叠）
* **问题**：缓冲落在不可 DMA 的内存属性区。
* **保障方案**：仿真 **A** 标签检查或 🟡 声明；真机必测。
* **验收预言**：若有标签，错误区分配 Fail；否则 08 链到 C24。
* **边界**：ESP32 缓存/DMA RAM 细则真机。

### C20 — 回调重入 / 延迟下半部

#### C20.1 ISR/回调内调用会 yield 的 DAL
* **问题**：回调里阻塞读传感器 → 重入或死锁。
* **保障方案**：**A** 回调上下文规则；**C** 上下文检测 Fault（交叠 C4.4）。
* **验收预言**：非法调用 Fault。
* **边界**：同 C4.4。

#### C20.2 传感器回调嵌套写执行器
* **问题**：输入回调直接驱动输出，形成同步环与优先级倒挂。
* **保障方案**：**A** 推荐队列解耦；**B** 可选检测「回调深度」。
* **验收预言**：超深嵌套告警；推荐模式用例通过。
* **边界**：不禁止所有同步耦合，但需文档风险。

#### C20.3 Workqueue / 延迟下半部顺序
* **问题**：假设 softirq/工作队列顺序，仿真无此层。
* **保障方案**：**B** 若 PAL 提供 deferred 作业则定义序；否则 **A** 不暴露。
* **验收预言**：有则测序；无则 N/A。
* **边界**：Linux softirq 语义不复制。

### C21 — 时间与计数回绕

#### C21.1 `uint32` ms / 滴答回绕
* **问题**：`now - last` 未用无符号差值，回绕后超时错乱。
* **保障方案**：**A** 编码规约；**C** 快进跨越回绕点的测试。
* **验收预言**：回绕窗口两边超时仍正确。
* **边界**：`s_virtual_us` 为 uint64，仍要测 App 自管 uint32。

#### C21.2 相对超时跨越快进
* **问题**：快进后相对 deadline 计算错误。
* **保障方案**：**B** 一律绝对 `wakeup_us`；单测。
* **验收预言**：快进后到期任务必醒。
* **边界**：与 C14 交叠。

#### C21.3 序列号 / 环形下标 wrap
* **问题**：seq 差值、ring index 取模错误。
* **保障方案**：**C** 专项单测；fuzz 种子。
* **验收预言**：跨 wrap 的 push/pop 正确。
* **边界**：业务自定义序列需自备测试。

### C22 — 电源 / 低功耗 / 时钟域

#### C22.1 light / deep sleep 唤醒
* **保障方案**：多数路径 **🚫** 或极简「睡眠=挂起任务 + 快进到唤醒源」；真机兜底。
* **验收预言**：若实现极简模型，唤醒源注入可醒；否则 08 🚫。
* **边界**：电流、唤醒延时波形 🚫。

#### C22.2 外设时钟门控
* **保障方案**：**🚫** 或显式 stub「访问未使能外设 → 错误码」。
* **验收预言**：有 stub 则测错误码；无则 🚫。
* **边界**：时钟树 🚫。

#### C22.3 Brownout / 欠压复位
* **保障方案**：复位原因注入见 C13.2；供电波形 🚫。
* **验收预言**：同 C13.2。
* **边界**：模拟欠压 🚫。

### C23 — 持久化 / NVS / 磨损

#### C23.1 断电写入撕裂
* **问题**：写到一半掉电导致损坏镜像。
* **保障方案**：**B** 可选「在 write 中点注入断电」；业务 CRC/双份校验同源测。
* **验收预言**：注入撕裂后启动走恢复/默认值路径。
* **边界**：Flash 物理磨损 🚫。

#### C23.2 键空间耗尽 / 满盘
* **保障方案**：**B** 配额；**C** 满返回错误。
* **验收预言**：耗尽错误码对齐。
* **边界**：磨损均衡算法不仿真。

#### C23.3 仿真「掉电」语义
* **问题**：刷新页面是否等于掉电不清。
* **保障方案**：**A** 文档：Worker 销毁 = 掉电；显式 snapshot API 另论。
* **验收预言**：无 snapshot 时重启无 NVS；有 snapshot 则测往返。
* **边界**：浏览器存储配额策略另文。

### C24 — 缓存 / 内存属性 / DMA RAM

#### C24.1 DMA 必须落在可 DMA 区
* **保障方案**：**A** 分配 API 分区；仿真标签检查或真机必测（交叠 C19.4）。
* **验收预言**：见 C19.4。
* **边界**：Xtensa 缓存一致性全模型 🚫。

#### C24.2 缓存一致性假设
* **保障方案**：🚫 日间轨；真机/Phase 5 抽样。
* **验收预言**：08 标 🚫；真机套件含 DMA+cache 用例。
* **边界**：刻意不保。

#### C24.3 IRAM / 放慢径指令位置
* **保障方案**：仿真 **🟡**；链接脚本差异文档化。
* **验收预言**：不因「仿真能链过」宣称 IRAM 约束已验。
* **边界**：真机链接与放慢径。

---

### C25 — 浮点 / 数值与编译器 UB

#### C25.1 有符号溢出 / 移位 UB
* **保障方案**：**C** UBSan；**A** 编码规范。
* **验收预言**：坏用例 Host 拦截。
* **边界**：Wasm 与 Xtensa 溢出包装行为可能仍有差异 → C12。

#### C25.2 NaN / Inf 传播与 flush-to-zero
* **保障方案**：**B** 控制律对 NaN 的策略单测；FPU 模式差真机抽测。
* **验收预言**：注入 NaN 后进入安全态或显式错误。
* **边界**：硬件 FTZ 模式 🚫 精确仿真。

#### C25.3 浮点确定性
* **问题**：跨平台浮点还原不一致导致 plant 轨迹漂。
* **保障方案**：**B** 固定软件 libm 或容差比较；golden 用容差带。
* **验收预言**：容差带内复现；超带失败。
* **边界**：bit-exact 跨所有 target 不承诺。
