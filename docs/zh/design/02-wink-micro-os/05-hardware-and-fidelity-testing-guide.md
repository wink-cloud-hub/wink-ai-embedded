# WinkMicroOS 硬件级仿真与真机测试真实性防御指南

本文档是 WinkMicroOS 在多 Target 构型下的测试设计规范。旨在指导开发者与 AI 编码助手在不同硬件条件（无真机、有裸板无外设、有完整外设）下如何开展高保真测试，并建立机制确保测试的“真实性”，杜绝“假成功（Fake Success）”的伪测试。

---

## 1. 无真实硬件时的仿真测试与“真实性防御”规范

在 Host 电脑或 WebAssembly 环境上跑仿真测试时，没有物理芯片和外设。为防止开发出“硬件其实跑不通，但单测全绿”的伪测试，必须遵守以下真实性防御规范。

### 1.1 杜绝 Stub 假成功（契约诚实性）
* **规范**：如果某个底层外设驱动尚未实现（如 `dal_gps`、`dal_eeprom` 目前仅是测试桩），其初始化和读写 API **绝对禁止**为了编译通过而直接 `return WINK_OK;`。
* **做法**：必须明确返回 `WINK_ERR_UNSUPPORTED`（参考 [ADR-0012 契约诚实原则](../../decisions/core/0012-contract-honesty-over-silent-degradation.md)），并在头文件和实现中打上 `@experimental Stub` 标签。

### 1.2 总线/寄存器事务级打桩（Bus-level Telemetry Mocking）
* **规范**：测试不能仅仅停留在“函数被调用了，返回成功”。必须校验调用所产生的**物理副作用**。
* **做法**：
  * **I2C 校验**：在 Host 的 `pal_i2c_transfer` 模拟器中，必须对传输地址和次数计数（`sim_i2c_transfer_count()`）。测试用例必须断言这些总线次数。例如：`dal_ssd1306_flush` 必须准确触发 9 次 I2C 传输。
  * **PWM 校验**：`pal_pwm_set_duty` 应记录通道被设置的占空比值（`sim_last_pwm_duty()`）。测试用例必须校验角度与占空比换算公式是否与硬件物理公式一致。
  * **GPIO 资源校验**：通过 `pal_resource_is_claimed` 校验引脚冲突和重复申请，防止多个 DAL 驱动无脑争用引脚。

### 1.3 虚拟时钟与时序波形注入
* **规范**：涉及测距、脉宽捕获等对时间高度敏感的外设，不能直接在驱动中 mock 出一个“距离”值，必须模拟真实的硬件电平跳变。
* **做法**：
  * 借助 `sim_set_echo_timing(rise_us, high_us)` 在测试中设置 Echo 引脚的硬件高电平开始时间和维持时间。
  * 驱动中通过真实的换算公式（$\text{距离} = \text{脉宽} \times 0.017$）读取该电平，并断言其输出是否符合物理。

### 1.4 防静默阻塞守卫（Wallclock Check）
* **规范**：非阻塞接口（如 `dal_ultrasonic_request_measurement`）应当在微秒级内立即返回。为了防范 AI 生成的代码在非阻塞接口中暗中使用 `while(poll)` 进行阻塞空等，测试必须进行时间开销检查。
* **做法**：
  * 使用 Host 系统的 `clock()` 测量循环调用 1000 次非阻塞 API 的总时间。
  * 断言总耗时必须远小于 100ms（单次调用应在微秒量级）。一旦存在阻塞空等，测试将超时失败。

## 2. 只有裸板无外设时的真机测试规范

当开发者手中只有一块 ESP32 裸开发板（如 DevKitC），没有任何传感器和执行器时，必须通过以下硬件回环方式进行“真机 PAL 契约”和“系统状态机”的验证。

### 2.1 情况 A：完全不接线（GPIO Matrix 内部自环）
该方法仅利用 ESP32 内部的引脚信号交换矩阵，不需要外部跳线。主要用于**验证底层驱动（PAL）的寄存器配置、中断分配与 ISR 正确性**。

```
                    ESP32 芯片内部 (GPIO Matrix)
              ┌──────────────────────────────────────┐
   LEDC PWM ──► [信号源] ── (绑定到同一个 GPIO) ──► RMT ──► 中断与 ISR
              └──────────────────────────────────────┘
                                │
                          无外部物理跳线
```

* **配置方法**：
  1. 将 PWM 发送端和 RMT 接收端指定在同一个物理引脚上（如 `GPIO4`）。
  2. 调用乐鑫 IDF 的信号绑定函数：
     ```c
     // 将 RMT 的输入信号源直接连接到该 GPIO 输出信号上
     esp_rom_gpio_connect_out_signal(GPIO_NUM_4, ledc_periph_signal, false, false);
     esp_rom_gpio_connect_in_signal(GPIO_NUM_4, rmt_periph_signal, false);
     ```
  3. 此时无需任何连线，PWM 产生的波形将直接送入 RMT，驱动 RMT 中断和 ISR。
* **测试用例期望**：
  * 主程序改变 PWM 占空比，RMT 捕获到的高电平持续微秒数同步改变。若数值不匹配，说明引脚时钟或 RMT 初始化分频代码在真机上有回归。

### 2.2 情况 B：使用 1 根跳线/回形针（软件影子模拟任务）
该方法需要一根杜邦线或金属导体，短接两个引脚（如 Trig 与 Echo）。主要用于**联调 DAL 层的协议层状态机和应用层业务逻辑**。

```
              ┌──────────────────────────────────────┐
              │             ESP32 裸板               │
              │  ┌──────────┐          ┌──────────┐  │
              │  │ GPIO4    │          │ GPIO5    │  │
              │  │ (Trig)   │          │ (Echo)   │  │
              └──┴───┬──────┴──────────┴──────┬───┴──┘
                     │                        ▲
                     └───────[ 物理跳线 ]──────┘
                                │
                 [影子任务监控 Trig, 在 Echo 产生响应脉冲]
```

* **配置方法**：
  1. 用杜邦线将 `GPIO4 (Trig)` 和 `GPIO5 (Echo)` 进行物理短接。
  2. 在系统初始化时，单独起一个最高优先级的 FreeRTOS 任务（影子任务 `mock_sensor_task`），用于模拟超声波硬件的行为：
     * 影子任务调用 `pal_gpio_read(TRIG_PIN)`，死循环阻塞或中断监听 Trig 引脚电平。
     * 当监听到 Trig 引脚被主程序拉高（说明发送了触发脉冲）时，影子任务等待 100微秒。
     * 影子任务将 Echo 引脚拉高，并使用 `esp_rom_delay_us(delay_us)` 模拟声波延迟，随后将 Echo 拉低。
  3. 主程序的 `dal_ultrasonic` 启动测距，由于物理引脚短接，影子任务产生的电平变化会被主程序真实读取。
* **测试用例期望**：
  * 可以通过修改影子任务中的 `delay_us` 模拟不同距离（如 $2940\mu\text{s} \to 50\text{cm}$）。
  * 验证避障小车等应用在真机上连续测距不卡死，且能在距离过近时输出正确的控制逻辑。

## 3. 测试规范回执表 (Fidelity & Bare-Board Audit Checklist)

无论是新增驱动还是修改既有驱动，提交 PR 前必须核对以下清单：

- [ ] **无硬件伪成功校验**：在 Host 测试中，是否有断言校验了具体的总线写入长度、引脚占用情况或计算精度？（拒绝仅验证 `WINK_OK`）
- [ ] **STRICT 编译校验**：在严格非阻塞构型 `-DWINK_STRICT_NONBLOCKING=1` 下，所有的 Blocking API（例如带有 `WINK_BLOCKING` 声明的方法）是否成功被编译器剔除？
- [ ] **真机退化校验**：若底层使用了真机特定的延迟/中断逻辑，是否使用 `#if defined(ESP_PLATFORM)` 进行了有效隔离，且 Host 侧有等价的虚拟时间流逝/手动中断注入测试？
- [ ] **引脚复用安全校验**：更改引脚定义后，是否通过了 `test_pal_resource` 的运行时抢占冲突断言？
