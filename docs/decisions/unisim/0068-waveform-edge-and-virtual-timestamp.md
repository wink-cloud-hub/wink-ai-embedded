## 背景（Context）

固件侧 `button_scan_10ms()` 严格置于 `main()` 的 `if (tick_flag)` 内部，每一拍精确对应 10ms 物理时基，连续 2 拍同值才确认按下/释放（20ms 消抖，响应延迟 20~30ms）。这要求仿真注入的按键有效脉宽**至少穿透 20ms 固件消抖**，工程上取下限为 $30{,}000\mu s$（30ms）。

旧契约用相对时延描述按压（“按下后保持 N ms”），在虚拟时钟快进（C14）下边沿时刻漂移；且按下沿与释放沿独立投递——若按下沿因调度迟到被推迟而释放沿不跟随，脉宽被压缩至消抖门限之下造成吞键；若整对中的一边被丢弃，则残留悬空释放/按下造成“按键卡死”（`btn_*_held` 锁存永不清除）。

## 方案比选（Options）

### 方案 A：相对时延注入（现状）

- **优点**：场景书写直观。
- **缺点**：快进下边沿时刻无锚点；迟到压缩脉宽无补偿规则；丢弃语义未定义。
- **判定**：不推荐。吞键与卡死无法根除。

### 方案 B：源端绝对时戳 + Generation 原子对（推荐）

- **优点**：边沿时刻锚定虚拟时钟 SSOT，可复现；原子对保证按压语义完整；迟到/丢弃有确定性规则（级联推迟 / 整对取消）。
- **缺点**：依赖外仓 D-004（Frontend 原子波形注入）实现源端时戳与 generation；Phase-A 存量场景仍用旧插件事件表达（300ms 按压天然满足 30ms 下限，不受影响）。
- **判定**：采纳。作为波形注入的正式契约。

### 方案 C：同步阻塞按压（固件 `while` 等待释放）

- **优点**：无。
- **缺点**：阻塞主循环，违反零容忍阻塞原则；看门狗（0.70s）与 10ms 时基全部被破坏。
- **判定**：否决。

## 决策结论（Decision）

1. **源端绝对时戳与单一真相（SSOT）**：注入源端以 `t_now = pal_wasm_get_virtual_clock_us()` 读取底层 `s_virtual_us` 作为边沿时刻锚点。
2. **Generation 与原子对**：每次物理按下生成自增 `generation++`；按下沿（`level=0, t_press=t_now`）与释放沿（`level=1, t_release=t_now + real_press_us`）作为**原子对**投递，不可拆分。
3. **迟到软钳位与释放沿级联推迟铁律**：若按下沿调度迟到被软钳位推迟至 `t_now`，其配套释放沿必须执行级联推迟，严格保证至少保留 $30{,}000\mu s$（30ms）有效脉宽穿透 20ms 固件消抖：
   $$t_{\text{release}} = \max\left(t_{\text{release}},\, t_{\text{press\_clamped}} + 30000\mu\text{s}\right)$$
4. **整对取消**：若因异常整体丢弃，必须**整对取消**（调 `cancel_waveform_generation`），严禁产生悬空释放造成“按键卡死”。
5. **引脚映射**：Header `P04` → 引脚编号 `4`，`P05` → `5`。

## 后果与约束（Consequences & Constraints）

- 场景书写约束：任何按键按压的有效脉宽不得低于 30ms（存量 16 场景均为 300ms 按压，天然满足，无需改写）。
- 固件侧配合：`button_init_post()` 上电卡键抑制保证上电已按住的键不产生 phantom 事件，与源端时戳共同消除上电竞态；去抖门限（2 拍/20ms）为本契约的另一端锚点，修改门限必须同步修订本 ADR 的 30ms 下限。
- Phase-B Task 5（8ms Bounce 注入回归）以前置依赖 D-004 到位为入口；Bounce 注入必须表达为“原子对内的毛刺序列”，不得破坏原子对语义。
- 本仓不实现 TS/前端侧波形引擎（外仓黑盒）；本 ADR 只固化**契约层**（时戳源、原子对、推迟公式、取消语义、引脚映射）。

## 遵循与后续（Compliance & Follow-up）

- 回写至 `wink-micro-app/mcs51_health_pot/docs/DESIGN.md` §1 按键行：Tick 守卫内双向 20ms 去抖（20~30ms 确认延迟）+ POST 卡键抑制。
- 场景侧：存量按压时长（400→700ms 等 300ms 脉宽）满足 30ms 下限；新建场景必须遵守。
- 后续专项 `PLAN-20260915-APPLIANCE-SAFETY-AND-GB4706` 的按键相关故障注入沿用本契约。
