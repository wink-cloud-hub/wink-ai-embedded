## 背景（Context）

`mcs51_health_pot` 的四个物理档位（详见实施计划 §3 联动基线表）对激励源有互斥要求：

| 档位 | 期望激励源 |
|---|---|
| 旧场景兼容档（`dryfire`，静态 25°C）/ 停滞超时档（`stall`，静态 55°C） | **脚本固定输入**（`valueNorm` 冻结注入） |
| 快速冒烟档（`fast-boil`，0.3L/1000W，94s 烧开）/ 标称量产档（`default_plant_config`，1kg/800W，462s） | **Plant 自激演算**（场景内零外部模拟注入） |

若同一场景混用两种激励源（C14.5 观测与注入竞态），Plant 写输入与脚本注入无明确屏障，干烧斜率判据（16s 窗/6 码）会看到非物理的跳变序列，导致误杀或漏杀。同时固件是**单镜像**（无法感知外部 JSON），若安全常数可被场景脚本覆盖，真机与仿真将出现无声分叉。

## 方案比选（Options）

### 方案 A：全脚本注入（现状延续）

- **优点**：零引擎改动；Phase-A 16 个场景全部可用。
- **缺点**：`fast-boil` 94s 自发烧开、标称 462s 长周期等闭环行为无法用冻结注入表达；每个场景手写温度曲线，物理一致性（功率×水量×升温速率）无人校验。
- **判定**：仅作为 Phase-A 存量资产过渡，不演进。

### 方案 B：Plant Profile 自激 + 场景只配物理环境（推荐）

- **优点**：Plant 按 `virtual_dt` Step-Lock 自激演算（C14.3），物理量自洽；场景脚本只声明物理输入环境（水质、功率、气压、水量），不描述温度轨迹；固件安全硬常数彻底隔离在 JSON 可达范围之外。
- **缺点**：依赖外仓 D-003（UniSim TS plant-profile 实现）到位后才能联调 `fast-boil`。
- **判定**：采纳。长期唯一演进方向。

### 方案 C：混合模式（场景可同时注入并叠加 Plant 输出）

- **优点**：灵活。
- **缺点**：两种激励源打架，斜率/超时判据看到的序列不可复现，违反 C14.5 步内顺序契约。
- **判定**：明确禁止。同一场景内两种激励源类别互斥。

## 决策结论（Decision）

1. **激励源二选一互斥**：每个场景必须声明且仅声明一种激励源类别——`脚本固定输入`或 `Plant 自激演算`（场景内零外部模拟注入）。禁止混用（C14.5）。
2. **场景只能配物理环境**：允许配置水质量量、标称功率、水质、气压等物理输入环境参数；**严禁配置固件安全硬常数**。
3. **安全硬边界防篡改**：固件内部干烧斜率判据（16s 窗 / 6 码 / 20s 武装 / 16 有效样本）与两级超时常数（Stage 1: 650s，Stage 2: 550s）属于绝对固化的物理安全防线，永不暴露为外部 JSON 可调参数。
4. **标称档基线**：`default_plant_config` 为 800W / 1.00kg / η=0.85 → 约 0.19°C/s → 25→100°C 约 462s；`fast-boil` 为 1000W / 0.30kg → 约 0.79°C/s → 约 94s 自发烧开（`timeoutUs: 150s`，固定 `prngSeed`，公差依 ADR-0055）。

## 后果与约束（Consequences & Constraints）

- Phase-A 存量场景保持脚本固定输入：`dryfire`（第 20 个 tick 秒斜率触发）与迁移后的 `dryfire-stall`（565s 断言 Stage 2，`timeoutUs: 600s`）已按本架构对账。
- Phase-B `fast-boil` 全自动闭环以前置依赖 D-003 到位为入口；在此之前不得用冻结注入伪造 94s 烧开曲线。
- Plant 实现必须遵守 C14.3（同一 `virtual_dt` 驱动 OS 与 Plant，禁读墙钟）与 C14.2（快进前排空 pin 事件）；数值比对走 ADR-0055 公差带。
- 本仓不实现 TS 侧 profile 引擎（外仓黑盒）；本 ADR 只固化**契约层**（分类、互斥、不可调清单、基线数值）。

## 遵循与后续（Compliance & Follow-up）

- 回写至 `wink-micro-app/mcs51_health_pot/docs/DESIGN.md` §1（五级安全故障防护行）与 §8（干烧保护时间行）：斜率法 + 650s/550s 单镜像硬兜底 + 脚本禁篡改声明。
- 场景侧：`health-pot-dryfire.scenario.json` / `health-pot-dryfire-stall.scenario.json` 注释已对齐激励源类别；`health-pot-fast-boil.scenario.json` 待 Phase-B 按本架构新建（Task 4）。
- 后续专项 `PLAN-20260915-APPLIANCE-SAFETY-AND-GB4706` 的故障注入矩阵必须遵守本 ADR 的激励源互斥与硬边界条款。
