## 1. 进入条件与阶段目标

QG-0 完成后开始实施；阶段内先完成真实采集与一条最小闭环，再扩大到交互、进程和事务。涉及未冻结设计选择的任务等待对应技术设计，不阻止其他独立任务。

当前核查确认三种独立缺口：

- [pipeline.py](../../../../wink-micro-app/vendor/esp_idfv61/.governance/loop/pipeline/pipeline.py) 缺 ProofPlan 时合成业务证据，实际 sdkconfig、工具链和 probe ABI 也存在贴标。
- [verify_afg_engine.py](../../../../wink-micro-app/vendor/esp_idfv61/.governance/tools/verify_afg_engine.py) 的 Pilot 直接构造记录，legacy 裁决包含应用 ID 特例；算法演示不能作为端到端验收。
- [mutation_runner.py](../../../../wink-micro-app/vendor/esp_idfv61/.governance/loop/afg/mutation_runner.py) 未物理应用其描述补丁，使用布尔失败判击杀；接入该类本身不能解决 I-05。

阶段出口是可复核的真实链路与拒绝能力，包含实际文件事务。它不自动写正式审计、verified 或看板，不把 Candidate Ready 当正式交付。

## 3. 核心实施约束

### 3.1 证据采集与统一身份

ProofPlan 在执行前解析、冻结并绑定摘要。模板解析、能力目录或身份读取失败保留具体诊断，不吞异常再套默认值。没有有效 Claims 时显式拒绝；“无外部 ProofPlan”也不得自动生成成功记录。原型生成的计划必须先完成复核和冻结，才进入验收。

从真实构建记录最终 sdkconfig、SoC、profile、工具版本及实际 probe 导出/返回结构；运行记录实际加载产物及 runner 身份。声明值和实际值不一致时拒绝，禁止 hash(config_id) 充当配置摘要或把常量 ABI 填成已验证。

Collector 从逐步骤结果生成 EvidenceRecord；每个结论引用真实报告与 Assertion ID，分类器验证报告完整性和归因。进程退出码和日志字符串仅为辅助诊断，不能单独签发成功或击杀。匹配器自检不得归类为 implementation_mutation。

### 3.2 变异必须生效且击杀能归因

1. 在独立 attempt 中复制冻结输入，保留原厂镜像及其摘要；只在隔离副本应用补丁。
2. 算子目标绑定确切文件/符号及适用配置；核验匹配数量与实际差异。零匹配、多义匹配、只加注释或 no-op 不进入击杀判定。
3. 从变异后的实际输入计算构建指纹，触发编译；保存命令、诊断、产物摘要与构建清单。缓存命中也须核验输入闭包与产物完整性。
4. Runner 明确加载该产物，保持原正常场景与预期不变；报告必须指出预定 Claim/Assertion 在契约时限内失败。
5. 基础设施异常、编译失败和无关早期断言失败分别分类；业务内 timeout 与宿主超时分别记录。
6. 用原始产物/新冷启动撤销扰动并重跑基线，记录清理和恢复。L1 故障处理按相反极性验证，不混计击杀。

每 Claim L2 最多 1 个；应用级默认 2 个只控制资源调度。必需 Claim 超过预算时按冻结基线拆分 attempt 或调整已确认预算，未执行项保持不完整。等价变异核验真实独立裁定及配置/算子/补丁/产物绑定，不能只看 JSON 中的 verdict 字符串。

### 3.3 BuildSandbox 与全依赖缓存

缓存指纹必须来自实际 app 源码、运行时/门面源码内容、头文件与生成物闭包、有效 sdkconfig、芯片/profile、编译器/SDK 及编译链接参数、补丁。工作树未提交修改也纳入，不以 Git SHA、默认空摘要或目录扩展名扫描代替实际依赖。

缺失依赖、读取失败、unknown 工具版本或损坏缓存不能悄悄命中旧产物；显式失败或执行有记录的完整重建。缓存写入/发布原子化，验证 metadata 和 artifact hash；并发 attempt 不共享可写构建目录，共享只读缓存需满足冻结协议。

复制 App 不是文件系统强隔离。按实际执行环境落实白名单写权限/执行边界，核验兄弟 attempt、原厂目录、正式证据和其他工作树不被污染；事后 git status 仅作补充。Job Object 解决进程归属，不替代文件写权限控制。

### 3.4 Job Object 与管道回收

每 attempt 先创建并配置 Job，再以挂起状态创建进程、加入 Job、验证归属并恢复执行。绑定失败终止该 attempt，不能退回无归属执行；禁止允许后代逃逸的 breakaway 设置。Job 句柄不泄漏/继承，清理须确认最后句柄与实际进程状态。

覆盖 build、Wasm、辅助 Worker 与授权的 agent 子进程。按冻结合同区分 graceful、force 和 stdout/stderr 关闭时限；清理失败是基础设施失败并停止受影响推广。无关进程不得被误杀。多次 real-OS 测试仅为证明矩阵内边界，不声称单次 500ms 超时证明全部进程路径。

### 3.5 密封、审计与晋升

- 依据 T0.2 冻结的规范完成稳定 payload，等待报告与日志关闭后计算清单摘要。summary、审计和衍生回执按版本化 envelope 方案绑定 payload，消除密封后的状态回写和自引用。
- 所有正式接受入口重算实际文件摘要并验证路径/身份、完整检查集合和版本有效性；AFG 回执不可缺省，不能只相信 ELIGIBLE 字段。需求审计和候选发布决定分别验证真实授权、范围及配置覆盖。
- 状态写入保留合法 `verified`；版本放入冻结元数据，不新增 verified_v1_1。正确旧包只读兼容；不补证据时不得转成新协议包。
- 先在同文件系统发布唯一的不可变归档目录，再获取登记锁，重读当前登记并执行 CAS，原子切换其引用，读回精确配置与摘要；派生看板按声明恢复协议更新。
- CAS 冲突重试仅针对允许的阶段；审计/输入仍有效时才重试，不能用重试重复删除/覆盖包。请求幂等键绑定配置与包摘要。
- 租约不得仅凭 TTL 到期删除活跃持有者的锁；冻结续约/所有权/fencing 或合适的本机 OS 锁方案，测试旧持有者恢复后不能继续提交。
- 每个提交边界的中断、占用或读回失败都有 journal/恢复路径；正式引用始终指向完整可验证包。测试事务使用隔离登记与明确测试信任域，合成审计只承担策略单测，不能充作正式签署。
