## 1. 背景与核心架构原则

### 1.1 业务功能外设 (Functional Devices) vs 基础设施外设 (Infrastructure Devices)
在嵌入式硬件电路开发中，必须严格区分两类芯片：
1. **业务功能外设 (Functional Devices)**：如 `keypad`, `led`, `button`, `relay`, `ultrasonic`。直接向 App 暴露 Role 接口（如 `get_key()`, `turn_on()`, `read_distance()`），驱动业务逻辑。
2. **基础设施/拓扑外设 (Infrastructure Devices)**：如 `io_expander` (PCF8574 I2C GPIO 扩展), `multiplexer` (74HC138 3-8 译码器), `i2c_mux` (TCA9548A I2C 开关)。**不向 App 暴露任何业务 Role API**，纯粹为硬件电路的物理选通、选址路由与通道解耦服务。

```text
                               ┌──────────────────────────────────────────────┐
                               │           Wink 芯片/外设分类体系            │
                               └──────────────────────┬───────────────────────┘
                                                      │
                       ┌──────────────────────────────┴──────────────────────────────┐
                       ▼                                                             ▼
         【业务功能外设 (Functional Devices)】                      【基础设施外设 (Infrastructure Devices)】
  - 向 App 暴露业务 Role API (如 set_speed, turn_on)          - 不暴露业务 Role API，纯粹为硬件拓扑/路由服务
  - 覆盖 7 大原生 Category:                                  - 声明 "category": "infrastructure"
    • input (按键/矩阵键盘)                                    - 覆盖 5 大拓扑 Provider 范式:
    • output (LED/蜂鸣器/继电器)                               • gpio_expander (IO扩展芯片 type: io_expander)
    • sensor (超声波/AHT20/MPU6050)                            • signal_mux (选通/译码器 type: multiplexer)
    • actuator (直流电机/舵机)                                 • bus_mux (总线开关 type: i2c_mux)
    • display (OLED/LCD)                                       • resource_provider (外置 ADC/PWM)
    • comm (串口/GPS)                                          • phy_transceiver (收发器/电平转换)
    • storage (EEPROM/Flash/SD卡)
```

### 1.2 架构硬防线（DAL 零侵入原则）
- **DAL 100% 纯粹同源（ADR-0040）**：`dal_keypad.c` / `dal_led.c` 内部只允许调用 `pal_gpio_read()` / `pal_gpio_write()`，**严禁写死任何 74HC138 或 PCF8574 控制代码**。
- **拓扑下发与多态路由**：从 MCU 原生引脚切换到 74HC138 选通或 PCF8574 I2C 扩展，纯粹由 **PAL 层引脚多态句柄 (`pal_gpio_handle_t`)** 与 **Codegen 有向无环图 (DAG) 拓扑排序** 自动透明下发。

## 2. 5 大 Schema 拓扑建模范式

在 `wink-app.json` 中，通过以下范式定义拓扑依赖与虚拟引脚/总线：

### 2.1 范式一：Virtual Pin 模式 (PCF8574 / 74HC595)
适用于通过总线/串行接口扩展逻辑 GPIO 的芯片：
```json
{
  "devices": {
    "io_expander": {
      "type": "io_expander",
      "variant": "pcf8574_i2c",
      "category": "infrastructure",
      "i2c_bus": 0,
      "i2c_addr": 32
    },
    "status_led": {
      "type": "led",
      "gpio_pin": "io_expander:P0",
      "active_high": true
    }
  }
}
```

### 2.2 范式二：Parent-Channel 选通模式 (74HC138 / CD4051)
适用于通过地址线/使能线分时复用选通特定通道的芯片：
```json
{
  "devices": {
    "sel_decoder": {
      "type": "multiplexer",
      "variant": "decoder_74hc138",
      "category": "infrastructure",
      "a0_pin": 14,
      "a1_pin": 15,
      "a2_pin": 16,
      "enable_pin": 17
    },
    "channel_led_3": {
      "type": "led",
      "parent": "sel_decoder",
      "channel": 3,
      "active_high": true
    }
  }
}
```

### 2.3 范式三：Virtual Bus 模式 (TCA9548A / PCA9544)
适用于解决 I2C 地址冲突或扩充总线槽位的复用开关：
```json
{
  "devices": {
    "i2c_switch": {
      "type": "i2c_mux",
      "variant": "tca9548a_i2c",
      "category": "infrastructure",
      "i2c_bus": 0,
      "i2c_addr": 112
    },
    "imu_front": {
      "type": "mpu6050",
      "i2c_bus": "i2c_switch:ch0"
    }
  }
}
```

## 3. C 语言底座架构改造与 PAL 引脚多态

### 3.1 PAL GPIO 句柄结构体多态改造 (`wink-micro-os/pal/include/pal_gpio.h`)

为支持虚拟引脚与选通通道，将传统的 uint16_t GPIO 抽象为多态联合体句柄：

```c
#ifndef PAL_GPIO_H
#define PAL_GPIO_H

#include <stdint.h>
#include <stdbool.h>
#include "wink_status.h"

typedef enum {
    PAL_GPIO_KIND_NATIVE = 0,          /**< MCU 原生 GPIO 引脚 */
    PAL_GPIO_KIND_VIRTUAL_PROVIDER = 1,/**< GPIO 扩展芯片虚拟引脚 (如 PCF8574:P0) */
    PAL_GPIO_KIND_MUX_CHANNEL = 2,     /**< 选通译码器通道 (如 74HC138:Ch3) */
} pal_gpio_kind_t;

typedef struct {
    pal_gpio_kind_t kind;
    union {
        struct {
            uint16_t pin_num;          /**< 物理 MCU GPIO 引脚编号 */
        } native;
        struct {
            void *provider_dev;        /**< 扩展芯片 C 驱动句柄指针 (如 dal_pcf8574_t*) */
            uint8_t virtual_pin;       /**< 扩展芯片引脚索引 (0..7) */
        } virtual_provider;
        struct {
            void *parent_mux;          /**< 译码选通器 C 驱动句柄指针 (如 dal_decoder_3to8_t*) */
            uint8_t channel;           /**< 选通通道索引 (0..7) */
        } mux_channel;
    } target;
} pal_gpio_handle_t;

WINK_WARN_UNUSED_RESULT
wink_status_t pal_gpio_init_handle(pal_gpio_handle_t handle, uint8_t mode);

WINK_WARN_UNUSED_RESULT
wink_status_t pal_gpio_write_handle(pal_gpio_handle_t handle, bool level);

WINK_WARN_UNUSED_RESULT
wink_status_t pal_gpio_read_handle(pal_gpio_handle_t handle, bool *out_level);

#endif /* PAL_GPIO_H */
```

### 3.2 PAL 路由入口与解算分发 (`wink-micro-os/pal/src/pal_gpio.c`)

```c
wink_status_t pal_gpio_write_handle(pal_gpio_handle_t handle, bool level) {
    switch (handle.kind) {
        case PAL_GPIO_KIND_NATIVE:
            return hal_gpio_write_native((wink_pin_t)handle.target.native.pin_num, level);

        case PAL_GPIO_KIND_VIRTUAL_PROVIDER:
            if (handle.target.virtual_provider.provider_dev == NULL) return WINK_ERR_INVALID_ARG;
            return dal_pcf8574_write_pin((dal_pcf8574_t *)handle.target.virtual_provider.provider_dev,
                                         handle.target.virtual_provider.virtual_pin, level);

        case PAL_GPIO_KIND_MUX_CHANNEL:
            if (handle.target.mux_channel.parent_mux == NULL) return WINK_ERR_INVALID_ARG;
            return dal_decoder_3to8_select_channel((dal_decoder_3to8_t *)handle.target.mux_channel.parent_mux,
                                                   handle.target.mux_channel.channel, level);

        default:
            return WINK_ERR_INVALID_ARG;
    }
}
```

## 4. 核心基础设施芯片 C 驱动设计

### 4.1 PCF8574 I2C IO 扩展器 (`dal_pcf8574.h` / `dal_pcf8574.c`)
- **硬件特性**：I2C 接口，扩展出 P0~P7 共 8 个准双向 GPIO 引脚。
- **驱动 API**：
  - `dal_pcf8574_init(dal_pcf8574_t *dev, const dal_pcf8574_config_t *cfg)`
  - `dal_pcf8574_write_pin(dal_pcf8574_t *dev, uint8_t pin, bool level)`
  - `dal_pcf8574_read_pin(dal_pcf8574_t *dev, uint8_t pin, bool *out_level)`

### 4.2 74HC138 3-8 译码器 (`dal_decoder_3to8.h` / `dal_decoder_3to8.c`)
- **硬件特性**：3 条地址选择线 (A0, A1, A2) + 可选使能线 (E1/E2/E3)，将 8 通道选通。
- **驱动 API**：
  - `dal_decoder_3to8_init(dal_decoder_3to8_t *dev, const dal_decoder_3to8_config_t *cfg)`
  - `dal_decoder_3to8_select_channel(dal_decoder_3to8_t *dev, uint8_t channel, bool enable)`

### 4.3 TCA9548A I2C 8通道开关 (`dal_tca9548a.h` / `dal_tca9548a.c`)
- **硬件特性**：I2C 扩展 8 个独立从机总线分支，避免从机地址冲突。
- **驱动 API**：
  - `dal_tca9548a_init(dal_tca9548a_t *dev, const dal_tca9548a_config_t *cfg)`
  - `dal_tca9548a_select_bus(dal_tca9548a_t *dev, uint8_t channel_mask)`

## 5. Codegen 引擎 DAG 拓扑排序与依赖解算

`wink-tools/tools/codegen/app_codegen.py` 的处理流程：

```text
               Codegen 有向无环图 (DAG) 解算流程
               
  wink-app.json
       │
       ▼
 1. 提取声明节点 (Extract Nodes & Dependencies)
    - Node A: io_expander (PCF8574, 入度 = 0)
    - Node B: status_led  (LED, 依赖 io_expander, 入度 = 1)
       │
       ▼
 2. 拓扑排序 (Topological Sort)
    生成初始化代码序列：
    Init Order: [io_expander] ──> [status_led]
       │
       ▼
 3. 模板渲染生成 app_device_tree_init()
    a. static dal_pcf8574_t io_expander;
       dal_pcf8574_init(&io_expander, &io_expander_cfg);
    b. static dal_led_config_t status_led_cfg = {
           .gpio_handle = {
               .kind = PAL_GPIO_KIND_VIRTUAL_PROVIDER,
               .target.virtual_provider = { &io_expander, 0 }
           }
       };
       dal_led_init(&status_led, &status_led_cfg);
```

## 6. Wasm / UniSim 仿真机制通道路由对接

遵照 [`08-channel-routing.md`](../../design/04-wasm-simulation/02-mechanisms/08-channel-routing.md)：
1. **通道 1 (Pin-Level)**：Wasm 侧触发 74HC138 A0~A2 引脚电平写操作，传入 `PinArbiter`，唤醒 `DecoderPlugin` 自动刷新对应选通通道的虚拟物理电平。
2. **通道 2 (Bus Protocol)**：Wasm 侧向 TCA9548A 发送总线切换事务，`BusRouter` 将后续 I2C 字节包路由至对应的子从机队列 (Sub-Slave Queue)。
