## 1. 架构总纲与映射原则

### 1.1 三维抽象定义与 `Variant` 维度解耦
本文档为 **Web UI Palette (外设拖拽面板)**、**Codegen 代码生成引擎**、**UniSim 仿真渲染桥接器 (Wokwi Bridge)** 以及 **C 语言 DAL (Device Abstraction Layer) 驱动库** 的唯一真理源 (Single Source of Truth, SSOT)。

**【权威元件基线与引脚规范】**
1. **基线对齐**：仿真元件 Tag 白名单与 Pinout 映射严密绑定于 vendored 本地源码 **`wokwi-elements@1.9.2`**（`src/*-element.ts` 中的 `@customElement` 注册名和 `pinInfo` 数组）。
2. **逻辑角色优先**：SSOT 大表中的“物理引脚拓扑”列一律统一表达为 DAL 的**逻辑引脚角色**（如 `[COM, NO, NC]` 或 `[VCC, GND, IN]`），其到 Wokwi 物理脚名（如 slide-switch 的 `1/2/3`）的转换下沉至 §4.6 契约层。
3. **Custom 降级**：凡 v1.9.2 不存在驱动模块的元件（如 `relay-module`, `a4988`, `tm1637-7segment`, `74hc595` 等），一律标为 **🔴 Custom**，由前端 Custom Element 插件 (`wink-custom-xxx`) 或 Codegen 虚拟网表合成渲染表象。

嵌入式外设全生命周期收拢于 **三级分类层级 (`Category` $\rightarrow$ `Type` $\rightarrow$ `Variant`)**：

- **`category` (顶级目录)**：硬件主要功能意图判定（`input`, `output`, `actuator`, `sensor`, `display`, `comm`, `storage`, `infrastructure` 8 大目录）。
- **`type` (控制语义护城河)**：底层通信协议、控制物理量单位（角度 / 步数 / 占空比 / 原始电压）以及统一 C API 接口结构体。物理控制量或 API 语义改变必须新建 `type`。
- **`variant` (同族变体避风港)**：驱动代码框架与核心 C API 不变的前提下，底层硬件变异的消化池。包含以下 6 类硬件变异维度：

  1. **物理引脚拓扑变异 (`affects_pins: true`)**：控制线/信号线数量或连接架构变化。
     - *实例*：`keypad` 的 `matrix_4x4` (8脚) vs `adc_ladder` (3脚)；`stepper` 的 `step_dir` (3脚) vs `four_wire` (4脚)；`relay` 的 `latching_dual_pin` (4脚) vs `direct_gpio` (3脚)。
  2. **通信接口总线变异 (`affects_pins: true`)**：底层物理总线传输介质切换。
     - *实例*：`mono_oled` 的 `ssd1306_i2c` (4脚) vs `ssd1306_spi` (7脚)；`lcd_char` 的 `i2c_pcf8574` (4脚) vs `parallel_4bit` (6脚)。
  3. **算法与响应曲线变异 (`affects_pins: false`)**：共享物理引脚拓扑，驱动层装载不同的传输函数或算法转换（如物理量转换 `lux`, `PPM`）。
     - *实例*：`analog_knob` 的 `standard` vs `logarithmic`；`analog_sensor` 的 `photoresistor` vs `gas_mq2_ao`（均为 3-Pin `[VCC, GND, AO]`；注：NTC 温度传感器已依据 ADR-0069 按边界 A 与小家电安规诉求正式提升为独立 Type）。
  4. **开关形态与触点状态变异 (`affects_pins: true` / `false`)**：物理引脚拓扑或开关机械触点特性、驱动电平极性分支变异。
     - *实例*：`button` 的 `push_button` (点动 2脚) vs `toggle_switch` (SPDT拨动 3脚 `[COM, NC, NO]`)；`led` 的 `rgb_common_anode` vs `rgb_common_cathode`。
  5. **采样状态机与解调协议变异 (`affects_pins: false` / `true`)**：底层硬件采样协议变异。若引脚变异（如单线/双线超声波），标记为 `affects_pins: true`；若仅 MCU 内部解调引擎差异（如 RMT vs GPIO），一律下沉至 `config.backend`。
     - *实例*：`encoder` 的 `x1_rising` vs `x4` (`affects_pins: false`)；`ultrasonic` 的 `hcsr04` (4脚) vs `single_pin_ping` (3脚)。
  6. **几何拓扑与坐标映射变异 (`affects_pins: false`)**：缓冲区物理阵列排布与数学坐标映射公式变异。
     - *实例*：`led_matrix` 的 `ws2812_strip` (1D 线性) vs `ws2812_matrix` (2D 阵列)；`lcd_char` 的 `1602` vs `2004` (几何参数进 `config_t`)。

#### 变体设计的 4 大硬裁决准则 (Boundary Invariants)：
- **边界 A (`Variant` vs `Type`)**：若物理控制量单位改变或核心 C API 签名遭到破坏，**必须新建 `Type`**。
- **边界 B (`Variant` vs `Config`)**：连续/离散物理标量参数（如 I2C 地址、PWM 采样频率、180°/270° 机械角度量程）归入 `dal_<type>_config_t` 结构体字段；仅在引起 **状态机/驱动逻辑分支变化**、**引脚映射表变化** 或 **Wokwi 仿真 UI Element 改变** 时，才提炼为 `Variant` 枚举。
- **边界 C (SOC 解调/传输引擎 vs `Variant`)**：MCU 内部硬件外设（如 ESP32 RMT vs GPIO、DMA 传输机制）不得作为 Variant（如删除 `rmt_hcsr04` 和 `ili9341_spi_dma` 中的 DMA），一律下沉至 `config.backend` 或真机驱动契约。
- **边界 D (单值 Variant 扩展预留原则)**：对于目前仅有一个主变体的 Type（如 `rc_servo`, `eeprom`, `gps`, `imu`, `tft`），在 C 枚举与 SSOT 中显式预留未来的第二个变体扩展位（如 `rc_servo` 预留 `continuous_rotation`），确保 `_Static_assert` 门禁具备类型演进价值。

#### 架构跟踪与处置说明 (Disposition Notes)：
- **P1-7 (SSOT 规范文档分层搬迁)**：当前 SSOT 正处于 `05-mono_oled`, `06-ultrasonic`, `07-led` 等重构计划推进期，暂留于 `implementation-plans/` 方便计划间交叉引用；待所有重构计划全量落地达到稳定终态后，将在 **v2.4.0** 统一提升至设计规范目录 `docs/design/specs/`。
- **P2-1 (`heart_rate_ao` 模拟心率归类)**：查验 `heart-beat-sensor-element.ts:7-11` 确认其 OUT 脚 signals 无 `analog()` 标注（Wokwi 源码无模拟输出）。`heart_rate_ao` 变体保留为 DAL 软件拟合接口，真机硬件与标准仿真推荐绑定 `threshold_do`。

### 1.2 外设时序类别归属规范（8+1 阶时序正交空间）

根据 [`peripheral-timing-classification-and-dal-architecture-guide.md`](../../todolist/peripheral-timing-classification-and-dal-architecture-guide.md)，所有外设在物理执行层面归入以下 **8+1 阶时序类别**：

- **Class 0：准静态电平与慢速软件消抖扫描类**（Relaxed GPIO / Polling，如 Button, LED, Relay, Keypad, 模拟量单次转换）
- **Class 1：纳秒脉宽自时钟编码类**（WS2812B RGB 灯带, 红外遥控 TX）
- **Class 2：微秒单总线自同步半双工握手类**（DHT11/22, DS18B20, 单引脚 Ping 超声波）
- **Class 3：慢速/中速同步串行移位类**（HX711 称重, TM1637 数码管, 74HC595 移位器）
- **Class 4：高速硬件总线流传输类**（硬件 I2C, 硬件 SPI, 硬件 UART，如 SSD1306, MPU6050, SHT30, GPS, TFT）
- **Class 5：高速脉冲输入与事件捕获类**（正交编码器, HC-SR04 Echo 脉宽捕获, 红外 RX）
- **Class 6：连续等时流式传输类**（I2S 音频 DAC / ADC 录音）
- **Class 7：多轴相位对齐与死区互补驱动类**（步进电机脉冲, 直流电机 H 桥, 舵机 50Hz PWM, 无刷逆变桥）
- **Class 8：高频硬实时闭环与硬件互锁管线类**（SimpleFOC 电流环 10kHz~20kHz, Timer-ADC 硬件联动）

> **关键架构断言**：在 `Type` 层级，由于存在多总线变体（如超声波含 HC-SR04 脉冲型、PING 单线型、UART 串口型、I2C 型），时序归属呈现多态性；但在 **`[Type + Variant]` 粒度上，每一个确切变体都有 100% 唯一的时序类别归属**。

### 1.3 SSOT 映射大表粒度定义 (Row Entity Invariant)

SSOT 映射矩阵的**每一行**代表一个确切的 **`[Wokwi Element (UI表现) + 物理引脚拓扑 (Pinout)]` 仿真实体**：

$$\mathbf{Table\ Row\ Entity} = \text{DAL Type} + \text{Wokwi Element (UI控件)} + \text{物理引脚拓扑 (Pinout)}$$

第二列命名为 **“匹配/支持的 `variant` 枚举”**，第三列明确标注该变体 **“唯一归属的时序类别”**。所有的 C 枚举命名统一强制归一化为 **`DAL_<TYPE>_VARIANT_<NAME>`**。

### 1.4 Wokwi Component 3 阶适配降级策略 (Fallback Strategy)

针对 `wokwi-elements@1.9.2` 组件库与现实硬件芯片的映射关系，制定以下 3 阶降级策略：

1. **🟢 Native Match (原生匹配)**：
   1:1 直接映射 `wokwi-elements@1.9.2` 源码中的标准 WebComponent（如 `potentiometer` $\rightarrow$ `<wokwi-potentiometer>`；`lcd1602` 设置 `"pins":"i2c"` $\rightarrow$ 4脚 I2C 背板）。
2. **🟡 Parametric Match (参数化拟合)**：
   Wokwi 虽无具体芯片专属 Element，但具备通用器件物理模型，通过修改 Wokwi JSON 属性参数（如 `rows`, `cols`, `vcc`）实现精确仿真。
3. **🔴 Custom / Synthetic Match (自定义组件 / 拓扑合成)**：
   `wokwi-elements@1.9.2` 完全缺失对应的驱动模块或器件（如 3 脚继电器模块、A4988 驱动板、TM1637、SHT30、24C02、GPS 等）。
   - **方案 A (Custom WebComponent)**：在 `embedded-frontend` 的 `wink-custom-elements` 中编写自定义 HTMLElement 模块。
   - **方案 B (Codegen Synthetic Netlist)**：DAL C 代码保持纯粹的逻辑脚抽象（如 `[VCC, GND, IN]`），由 Codegen 引擎在生成 `diagram.json` 时自动将逻辑脚与 Wokwi 裸件回路做合成对接（详见技术方案 [`2026-08-07-bare-component-driver-module-synthetic-netlist-design.md`](../../tech-designs/frontend/2026-08-07-bare-component-driver-module-synthetic-netlist-design.md)）。
   - *特别盘点 (继电器裸件)*：Wokwi@1.9.2 原生存在 `wokwi-ks2e-m-dc5` DPDT 8脚裸继电器。**注意**：在 v1.9.2 中为纯 SVG 视觉壳（无物理开关动作仿真）；线圈 `COIL1` 经三极管驱动、`COIL2` 接地；触点组只取 P1/NO1/NC1 单极（另一极 P2 触点悬空）；Codegen Synthetic Netlist BOM 包含 `wokwi-resistor` 限流电阻与续流二极管。`ks2e` 仅服务 `direct_gpio` 非闭锁变体，不服务 `latching`。

## 4. 变体设计的架构护城河硬规范 (Variant Invariants)

在编写具体外设分计划和代码落地时，必须强制遵守以下 **7 大不变量规范**：

### 4.1 变体枚举零歧义原则 (Deterministic Pin Map Invariant)
每一个 `variant` 关联的引脚数量（Pin Count）与引脚功能列表（Pin Roles）必须是**绝对唯一且静态确定**的。
- ❌ **严禁**：在同一个 `variant = "standard"` 内部通过 if-else 动态决定是 2 脚模式还是 4 脚模式。
- ✅ **正确**：拆分为两个确切变体：`variant = "step_dir"` (3脚) 与 `variant = "four_wire"` (4脚)。
- 💡 **特例（受限兜底变体 Bounded Custom Variant）**：对于几何规格、位数或字符映射无法单项穷举的外设（如 `keypad` 的 `custom` 变体，及 `seg_display` 的 `direct_gpio_n_digit` 变体），允许声明为受限兜底变体。C 配置结构体必须按系统最大上限（如 `keypad` 预留 `MAX_ROWS=4, MAX_COLS=4` 8Pin 数组；`seg_display` 预留 `MAX_DIGITS=8` 位选脚数组）做**静态 ABI 空间分配**；实际激活脚数由 `num_rows/num_cols` 或 `digits` 运行时设定，未用到的引脚槽位统一由 Codegen `variant_fields` 自动置 `-1` 哨兵。

### 4.2 变体只进 POD Config，不污染 C 公开 API
`variant` 仅仅是驱动初始化的配置选项，统一放在 `dal_<type>_config_t` 结构体中。C 语言对外公开函数签名严格保持 `dal_<type>_init()`, `dal_<type>_read()`, `dal_<type>_set()`，**绝对禁止**按 `variant` 派生子函数。

### 4.3 `affects_pins` 前后端联动契约
在 Codegen YAML 的 `fields.variant` 中，必须明确标注 `affects_pins: true | false`。表格中记录的是行级布尔值；YAML 字段级 `affects_pins` 为该 Type 任一行的逻辑或。当前端切换 `affects_pins == true` 的变体时，自动触发编辑器**引脚解绑与重排**。

### 4.4 芯片别名 (IC Aliases) 自动归一化
现实芯片型号名（如 `SG90`, `HC-SR04`, `SSD1306`, `DHT22`）仅作为 **Codegen Aliases 数据库** 存在。Codegen 解析用户输入的芯片型号时，自动归一化展开为对应 DAL `type` 与 `variant`，并将具体物理参数填入 `config_t`。

### 4.5 复合硬件模块的 DAL 拆解与 Wokwi 画板绑定契约
对于现实中集成多个物理功能的复合器件（如带按键的 KY-040 编码器、双轴模拟摇杆）：
- **DAL C 层单一职责**：DAL C 驱动拒绝“巨型复合驱动”。KY-040 模块拆解为 1 个 `encoder` 实例与 1 个 `button` 实例；模拟摇杆拆解为 2 个 `analog_knob` 实例与 1 个 `button` 实例。
- **Web UI & Codegen 映射契约**：前端拖放 1 个 `<wokwi-ky-040>` 时，Codegen 解析 JSON 自动提取 Netlist，合成派生出 2 个 C DAL 驱动实例代码。
- **网表节点短接与 tie-down 规则**：对于 `wokwi-dip-switch-8`（16脚，8路独立 SPST），拆解为 8× `button` 实例时，Codegen 自动将每一路 1b..8b 端短接到 GND/VCC 电源网表；对于 `wokwi-pushbutton`（4脚），Codegen 自动将内部等电位脚 (`1.l=1.r`, `2.l=2.r`) 合并为逻辑节点 A/B 后再进行引脚绑定与接地短接。

### 4.6 Wokwi 拓扑绑定与 C `config_t` 契约分离规范
明确区分前端 UI / 仿真渲染层与 C 驱动 / Codegen 工具链层的映射边界：

1. **前端外设包独立掌控物理拓扑 (`peripherals/builtin/`)**：
   Wokwi 组件绑定、引脚相对坐标 (`relX`, `relY`)、默认 Wire Net 连接以及外观 ID（`defaultAppearanceId`）完全下沉于前端 TypeScript 外设包（如 `peripherals/builtin/<type>/<version>/src/variants.ts` 中的 `PinsOverlayMap`）。
2. **DAL C 层与 Codegen YAML 纯粹专注于 C 配置**：
   DAL C 驱动保持高层逻辑引脚抽象（如 `i2c_port`, `i2c_addr` 或 `trig_pin`, `echo_pin`），完全不感知 Wokwi 的底层组件名或物理引脚编号。Codegen Driver YAML (`wink-tools/tools/codegen/drivers/*.yaml`) 仅维护 C `config_t` 结构体字段列表与 `variant_fields` 未选中引脚 `-1` 哨兵裁剪。

3. **`seg_display` `direct_gpio_n_digit` Per-N 物理引脚映射对照表**：
   `wokwi-7segment` 元件的 `pinInfo` 随 `digits` 属性动态演变。受限兜底变体在 Codegen / TS 外设包映射时必须严格遵循以下物理脚对照规则：

| 位数 ($N$) | 真实物理脚数 | 物理引脚集合 | 哨兵与网表连线说明 |
|:---:|:---:|---|---|
| **$N=1$** | 10Pin | `[A..G, DP, COM.1, COM.2]` | 属于 `direct_gpio_1d` 变体，无扫描直驱；**注意**：源码脚名含点号 (`COM.1`/`COM.2`)，Codegen 网表连线必须使用含点号形式 |
| **$N=2$** | 10Pin | `[A..G, DP, DIG1, DIG2]` | 属于 `direct_gpio_n_digit` (🟢 Native)；无 `CLN`，无独立 `COM`；`dig_pins[2..7]` 与 `colon_pin` 赋 `-1` 哨兵 |
| **$N=3$** | 11Pin | `[A..G, DP, DIG1, DIG2, DIG3]` | 属于 `direct_gpio_n_digit` (🟢 Native)；无 `CLN`，无独立 `COM`；`dig_pins[3..7]` 与 `colon_pin` 赋 `-1` 哨兵 |
| **$N=4$** | 14Pin | `[A..G, DP, DIG1..DIG4, COM, CLN]` | 属于 `direct_gpio_n_digit` (🟢 Native)；`COM` 脚 (pin 7) 在 4 位多路复用中属于活跃/合成脚；`dig_pins[4..7]` 赋 `-1` 哨兵 |
| **$N=5..8$**| — | — | Wokwi v1.9.2 源码 fallback 回 1 位脚表，物理引脚无法多路复用；标记为 🔴 Custom/Synthetic |

### 4.7 基础设施外设 (Infrastructure) 的 Pin Provider 代理挂载规范
`io_expander / multiplexer / i2c_mux` 属于系统级硬件总线/引脚提供者。依据 ADR-0004 §演进路径 §3，向系统提供配置期静态绑定的 Provider 接口/回调集合 (`dal_gpio_provider_t` / `dal_i2c_bus_provider_t`，目前为规划态，随 28-30 型落地引入)。上层 `dal_button` 或 `dal_led` 句柄挂载在由它们派生的虚拟引脚上。详细的拓扑建模、DAG 初始化排序与落地计划见 [`00.6-infrastructure-devices-plan.md`](00.6-infrastructure-devices-plan.md) 及技术设计 [`2026-08-03-hardware-topology-and-infrastructure-devices-design.md`](../../tech-designs/frontend/2026-08-03-hardware-topology-and-infrastructure-devices-design.md)。

## 5. 多端自动化校验与集成契约 (Tooling Integration)

### 5.1 CI / Lint 机械化门禁与 C 断言
`wink` 工具链与 C 编译器对本 SSOT 强制校验以下机械化门禁：
1. **Wokwi Tag 注册表白名单门禁**：Wokwi element tag 必须存在于 **vendored v1.9.2 源码** `src/*-element.ts` 的 `@customElement` 注册表，或在 `wink-custom-` 注册白名单报备。
2. **C 变体双重静态断言模板 (`_Static_assert`)**：C 头文件中必须包含双重静态断言，同时捕抓“追加忘更新 N”与“中间插入顺延末值”两类静默错误：
   ```c
   // enum 类型追加 _COUNT 枚举成员；uint8_t 类型（如 mono_oled）使用独立 #define 定义 COUNT
   _Static_assert(DAL_<TYPE>_VARIANT_COUNT == <N>,
                  "Variant count mismatch with SSOT §2 and codegen YAML");
   _Static_assert(DAL_<TYPE>_VARIANT_<LAST> + 1 == DAL_<TYPE>_VARIANT_COUNT,
                  "Sequential variant ordering error: last member index check failed");
   ```
3. **`affects_pins` 引脚差异断言**：仅在标记为 `affects_pins: true` 的变体行之间进行两两引脚字段差异断言（`affects_pins: false` 算法变体不参与此断言）。若 Type 级引脚逻辑或 OR 为 true，前端切换变体时自动触发引脚重排。
4. **零 `wokwi_binding` 冗余约束**：Codegen Driver YAML 严禁放入 `wokwi_binding` 字段；前端 UI 外设包 (`peripherals/builtin/.../variants.ts`) 直接以 SSOT 大表 `element` 列为权威依据。

### 5.2 SSOT ↔ Codegen 真实工具链集成校验矩阵

| SSOT 规范维度 | 自动化校验引擎 / 工具 | 真实执行命令 |
|---|---|---|
| Variant 枚举与 `variant_fields` 契约 | `yaml_schema.py` (字段与 Key 强匹配) | `python -m tools.codegen.schema.yaml_schema` |
| `-1` 哨兵引脚裁剪与模板渲染 | `emit_config.py` (非活跃引脚自动赋 -1) | `pytest tools/codegen/tests/` |
| C ABI 尺寸稳定 & 变体数量 | C 编译器 `_Static_assert` 断言 | `cmake --build .` |
| C 代码风格与静态头文件规则 | `wink lint` 静态分析引擎 | `python wink.py lint` |
