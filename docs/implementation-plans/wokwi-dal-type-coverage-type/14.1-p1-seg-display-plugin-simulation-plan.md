## 0. v2.0.0 修订摘要（相对 v1 的关键变更）

1. **修正插件契约硬伤**：`stateChannels` 仅支持 `number|boolean|string`（无 `array`）；`onPinChange` 真实签名为 `(pin: number, level: LogicState, atUs: bigint)`，pin 是 **MCU 引脚号**（需反查表），电平是**四值逻辑**（LOW/HIGH/**HI_Z**/CONFLICT）。
2. **节流/余辉必须建立在虚拟时钟上**：使用 `ctx.nowUs()/ctx.deferUs()` 与官方 `createThrottlePublish()`，禁止墙钟 `setInterval`；暂停、倍速、单步、快照回放、确定性单测均依赖此点。
3. **显示模型从二值 POV 升级为占空比亮度积分模型**（§3），可自然复现**鬼影/拖影、刷新过慢变暗闪烁、多位同时选通**三类教学高频故障。
4. **极性拆分为段选/位选两个独立有效电平**（§2.2），覆盖"共阴/共阳 × 三极管/译码器位驱"四种真实板级组合；`commonAnode` 仅作一键预设。
5. **位数由 variant 承载**（引脚数随位数变化，manifest 引脚集静态）：`direct_gpio_8d/4d/2d/1d`。
6. **补齐生命周期钩子**：`onReset / serializeState / deserializeState / onPropertyChange / onDestroy`；开发期 manifest 设 `status: 'draft'`，M5 转正。
7. **明确跨仓联动点**（§7）：运行时为文件系统自动发现（无需注册），但 unisim 源码仓 SSOT 测试的 `EXPECTED_DAL_TYPES` 清单必须同步加 `seg_display`；前端 worker 无需改动（走通用 `pluginChannels` 通道）。

## 1. 任务背景与架构目标

### 1.1 为什么将插件与仿真独立为 Part 1？

根据 SSOT §4.6 规范，Wokwi/UniSim 仿真组件拓扑与 DAL C 驱动层具备天然解耦属性：

1. **关注点分离（Pin-Level Decoupling）**：前端外设插件只关注**物理引脚电平变沿**与**视觉暂留渲染**。无论电平来自高级 DAL 驱动还是纯 8051 汇编/裸机代码，仿真层均一视同仁。
2. **测试先行（Shift-Left Testbench）**：先建设高保真的多位数码管仿真插件，立即为 Part 2（8051 裸机验证）与 Part 3（跨平台 DAL 驱动）提供可视化"仿真测试台"。
3. **8051 经典形态优先**：高校教学与传统工业中最普遍的数码管形态为 **8 位共阴/共阳动态扫描数码管**（8 根段选线并联 + N 根独立位选线）。本计划重点为该形态构建坚实仿真模型。
4. **教学故障可视化（v2 新增目标）**：插件不仅要"正确时显示正确"，还要"错误时显示真实硬件的错误现象"——鬼影、暗闪、多位串显是 51 动态扫描教学中排名第一的调试场景，二值模型会把这些 bug 完全藏掉。

### 1.2 线程模型与性能约束（澄清）

仿真插件运行在 **wasm simulation worker** 内，热路径不接触 Vue 响应式系统。"事件风暴"的真实成本是：

- worker 内边沿回调开销（8051 1kHz 8 位扫描 ≈ **每秒 1.6 万~3.2 万次 `onPinChange`**，每次 16 根线中仅 1 根变化）；
- worker → 主线程的 state 发布（结构化克隆批量快照，约 30fps）。

因此性能要求明确为：

- **边沿回调 O(1)、零堆分配**：预分配 `Uint8Array`，热路径不创建对象/数组/字符串；
- **发布走虚拟时间节流**：`createThrottlePublish(intervalUs = 33_000n)`（30fps），负载为定长二进制；
- 渲染端（主线程）每帧只改 SVG `fill-opacity/fill`，不动 DOM 结构。

## 2. 硬件拓扑与引脚契约规范

### 2.1 N 位数码管物理引脚拓扑 (Pinout Topology)

动态扫描数码管标准接口为 **8 根段选线 + N 根位选线**（8 位共 16 脚，4 位 12 脚，2 位 10 脚，1 位静态 8~9 脚）。

| 引脚分组 | 引脚名 | 物理语义 | pinType | simRole | 51 典型连接（仅端口位，不作封装脚号） |
|---|---|---|---|---|---|
| **段选组 (8)** | `A` | 顶部横段 | `digital_in` | `seg_a` | P0.0 |
| | `B` | 右上竖段 | `digital_in` | `seg_b` | P0.1 |
| | `C` | 右下竖段 | `digital_in` | `seg_c` | P0.2 |
| | `D` | 底部横段 | `digital_in` | `seg_d` | P0.3 |
| | `E` | 左下竖段 | `digital_in` | `seg_e` | P0.4 |
| | `F` | 左上竖段 | `digital_in` | `seg_f` | P0.5 |
| | `G` | 中间横段 | `digital_in` | `seg_g` | P0.6 |
| | `DP` | 小数点（段选线共享，**每位位置各有一个圆点**，由该位选通期间 DP 电平决定） | `digital_in` | `seg_dp` | P0.7 |
| **位选组 (N)** | `DIG1` | 第 1 位（最左/最高位）公共端 | `digital_in` | `dig_1` | P2.0 |
| | `DIG2` … `DIG{N}` | 其余位公共端，`DIG{N}` 为最右/最低位 | `digital_in` | `dig_2`…`dig_n` | P2.1 … P2.(N-1) |

> **勘误（v1）**：v1 表格括号内标注的 DIP-40 封装脚号错误（P2.0 是 Pin 21 而非 16；P0.0 是 Pin 39 而非 "Pin 0"）。本版只保留端口位，封装脚号不在插件契约范围内。
>
> **别名（aliases）**：每脚提供小写别名（`a`/`seg_a`、`dp`、`dig1`/`digit1` 等）以兼容 wink-app/device-tree 旧键名；**同一 manifest 内 aliases 不得重复**（SSOT 对齐测试强制）。
>
> **1 位静态变体 `direct_gpio_1d`**：`DIG1` 标记 `required: false`；未接线时该位按"永久选通"处理（静态直驱，公共端硬件直连 GND/VCC）。

### 2.2 极性模型：段选/位选有效电平独立配置

真实 51 开发板上，数码管公共端极少直接接 MCU 引脚——通常经三极管（NPN/PNP）或 74HC138 译码器驱动，因此 **MCU 引脚有效电平 = 数码管制造极性 × 位驱电路**，共四种组合：

| 板级电路 | 段选有效电平 `segActiveLevel` | 位选有效电平 `digitActiveLevel` |
|---|:---:|:---:|
| 共阴直驱（教学默认） | `high` | `low` |
| 共阳直驱 | `low` | `high` |
| **共阴 + NPN/逻辑反相位驱**（大量国产教学板） | `high` | **`high`** |
| **共阳 + PNP/同相位驱** | `low` | **`low`** |

**属性定义（manifest.properties）**：

| 属性 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `variant` | string | `direct_gpio_8d` | 拓扑变体（决定引脚集） |
| `segActiveLevel` | string enum(`high`/`low`) | `high` | 段选线点亮电平 |
| `digitActiveLevel` | string enum(`high`/`low`) | `low` | 位选线选通电平 |
| `commonAnode` | boolean | `false` | **一键预设**，仅在两个 level 属性未被显式设置时生效：`true` → seg=`low`/dig=`high`；`false` → seg=`high`/dig=`low`。解析优先级：显式 level > commonAnode 预设 |
| `color` | string enum | `red` | 与 `led` 插件对齐：`red/green/blue/yellow/white/orange/purple` |
| `glow` | boolean | `true` | 辉光开关（UI 侧） |
| `brightness` | number 0~1 | `1.0` | UI 主亮度倍率 |
| `label` / `flip` / `appearanceId` | — | `''`/`false`/`seg_display_8` | 与 led/mono_oled 惯例一致 |

**四值逻辑处理规则**（`LogicStates`：LOW=0, HIGH=1, HI_Z=2, CONFLICT=3）：

- 位选选通条件：`digitActiveLevel==='high' ? level===HIGH : level===LOW`；
- 段选点亮条件：`segActiveLevel==='high' ? level===HIGH : level===LOW`；
- **HI_Z（高阻/未驱动）永不选通、永不点亮**——51 复位/上电瞬间 P0~P2 全为高阻，必须显示全灭而非乱码；
- CONFLICT 按未驱动处理，并限频 `ctx.system.log.warn` 提示总线冲突。

## 3. 动态扫描仿真模型：占空比亮度积分器 (Duty-Cycle Brightness Integrator)

### 3.1 为什么不用二值 POV

v1 的"30ms 内亮过就保持点亮"是二值模型，能仿真正常扫描，却会掩盖教学中最高频的三类真实故障：

| 真实现象 | 二值 POV | 亮度积分模型 |
|---|---|---|
| **鬼影/拖影**：切位前不消隐（先送段码后关位选，或时序反了），邻位短暂显示错误段码 | 不可见 | 邻位出现低亮度鬼影段（亮度 ~5–15%）✅ |
| **刷新过慢**：扫描间隔写错（>10ms/位） | 照常稳定显示 | 亮度下降 + 可见闪烁 ✅ |
| **多位同时选通**：位选逻辑错误导致两个公共端同时导通（硬件 sneak path） | 行为未定义 | 两位同显且偏暗，插件限频告警 ✅ |
| 正常 1kHz×8 位扫描（每段占空 ~1/8） | 全亮 | 稳定高亮度显示，观感与真实器件一致 ✅ |

### 3.2 模型规格

为每个 **(位 d, 段 s)** 维护一个亮度累加器 `bright[d*8+s] ∈ [0,255]`（`Uint8Array`，预分配）。

**边沿事件中惰性积分**（`onPinChange` 内，以 `atUs` 虚拟时间戳驱动）：

```text
integrateTo(nowUs):
  dtUs = clamp(nowUs - lastEdgeUs, 0, MAX_DT)        // MAX_DT = 100_000us，暂停后恢复不产生巨量衰减
  for d in 0..nDigits-1:
    digitActive = 位线 d 当前选通（按 §2.2 规则，HI_Z=false）
    for s in 0..7:
      segActive = 段线 s 当前点亮
      lit = digitActive && segActive
      // 泄漏积分器（τ 为虚拟时间常数）
      if lit:  bright[k] = min(255, bright[k] + dtUs * CHARGE_RATE)
      bright[k] = max(0, bright[k] - bright[k] * (dtUs / DECAY_TAU_US))
  lastEdgeUs = nowUs
```

**默认常数（虚拟时间，可在 M3 单测中整定）**：

| 常数 | 默认值 | 依据 |
|---|---|---|
| `DECAY_TAU_US` | `20_000`（20ms） | 人眼视觉暂留 + 荧光余辉量级 |
| `CHARGE_RATE` | `255 / 2_000`（累计点亮 2ms 即饱和） | 8 位 1kHz 扫描下每段每 20ms 窗口累计点亮 ~2.5ms，正常扫描饱和；鬼影（切换毛刺 ~10–50µs/8ms 周期，占空 <1%） equilibrium 亮度远低于逻辑阈值 |
| `LOGIC_THRESHOLD` | `120` | 亮度 ≥ 此值判定该段"逻辑点亮"，用于段码译码与 `segMask` |
| `GHOST_MAX_BRIGHT` | `40` | 单测断言鬼影段亮度上限 |
| `PUBLISH_INTERVAL_US` | `33_000`（30fps） | 与 worker 显示采集节奏对齐 |

**派生量（发布时计算，不入热路径）**：

- `segMask[d]`：8 位掩码（bit0=A … bit7=DP），`bright[d*8+s] ≥ LOGIC_THRESHOLD` 置位；
- `text`：`segMask` 查 7 段字形表译码为字符（0-9/A-Z/空格/`-`；不可识别段型输出 `�`），用于无障碍 aria-label 与 observe `display_text` 钩子；
- `scanHz`：统计窗口内各位选通沿（无效→有效）频率，反映真实刷新速率；
- `activeDigits`：积分窗口内同时选通的最大位数（>1 即多位冲突）。

### 3.3 发布与余辉拖尾 (Tail Decay)

- 使用官方节流器（虚拟时间驱动，内部走 `ctx.nowUs()/ctx.deferUs()`）：

  ```ts
  private throttle = createThrottlePublish({
    ctx: () => this.ctx,
    intervalUs: 33_000n,
    publish: (nowUs) => this.publishFrame(nowUs),
  });
  ```

- **边沿停止后的余辉拖尾**：最后一帧后若无新边沿，节流器不再触发，画面会冻结。`publishFrame` 末尾检查：若任一 `bright > GHOST_MAX_BRIGHT`，用 `ctx.deferUs(PUBLISH_INTERVAL_US, cb)` 链式补发（generation 令牌防护，reset/destroy 时取消），直到全暗或最多 ~6 帧（≈200ms 虚拟时间）。
- **发布负载**（全部定长、可结构化克隆；`Uint8Array` 在 worker→主线程快照中原样保留）：
  - `bright`: `Uint8Array(nDigits*8)` —— 渲染用亮度矩阵；
  - `segMask`: `string`（`JSON.stringify(Array.from(mask))`）—— 逻辑态/调试用；
  - `text`: `string` —— 译码文本；
  - `scanHz` / `activeDigits`: `number`。

### 3.4 多位同时选通检测

积分循环中若 `activeDigits > 1`：该窗口内所有选通位的点亮段按相同 `lit` 累加（模拟两位并联偏暗同显）；同时以虚拟时间 ≥100ms 限频调用 `ctx.system.log.warn('[seg_display] multiple digits driven simultaneously (N)')`，并在 `activeDigits` 通道体现。

## 4. UniSim 插件契约落地规范

> 以下签名均对照 `@wink-ai/unisim` 源码（`packages/unisim/src`）与 npm 0.1.8 d.ts 核实。

### 4.1 基类与清单

- 继承 `BaseSimulationPlugin<SegState, SegProps>`（**不要**用 `SimpleGpioPlugin`——它只服务单信号脚 LED/button 模式）。
- manifest 经 `normalizeManifest({...})` 声明：
  - `type: 'seg_display'`，`category: 'display'`，`version: '1.0.0'`；
  - `timingModel: 'event-driven'`（边沿驱动；积分在边沿内惰性完成，无需 `step-lock`）；
  - `status: 'draft'`（M2–M4 开发期；M5 验收时删除该字段转 `stable`，前端 binder 才会收录）；
  - `pins`：见 §2.1（随 variant 由 `manifestFactory` 产出）；
  - `properties`：见 §2.2；
  - `stateChannels`（**类型只能是 number/boolean/string**）：

    | channel | type | default | show | 说明 |
    |---|---|---|:---:|---|
    | `bright` | `string` | `''` | false | `Uint8Array` 亮度矩阵（发布时直接发 TA，通道类型 string 仅为过 schema） |
    | `segMask` | `string` | `'[]'` | true | 逻辑段掩码 JSON 数组 |
    | `text` | `string` | `''` | true | 译码文本 |
    | `scanHz` | `number` | `0` | true | 实测扫描刷新频率 |
    | `activeDigits` | `number` | `0` | false | 窗口内同时选通最大位数 |
  - `events: {}`（无入向事件；纯显示 sink）。
- 默认导出契约（FS 发现器强制校验）：`export default { manifest, manifestFactory, PluginClass }`。

### 4.2 引脚反查映射（关键）

`onPinChange(pin, level, atUs)` 的 `pin` 是 **MCU 引脚号（number）**，不是 manifest 引脚名。在 `onBound(ctx, pinMapping, props)` 中建立反查表：

```ts
protected onBound(ctx, pinMapping, props): Partial<SegState> {
  this.segPinOf.clear(); this.digPinOf.clear();
  for (const segName of ['A','B','C','D','E','F','G','DP']) {
    const mcu = pinMapping[segName];
    if (mcu !== undefined) this.segPinOf.set(mcu, SEG_INDEX[segName]); // 0..7
  }
  for (let d = 0; d < this.nDigits; d++) {
    const mcu = pinMapping[`DIG${d + 1}`];
    if (mcu !== undefined) this.digPinOf.set(mcu, d);
  }
  // 1d 静态：无 DIG 映射 → this.staticDrive = true（位 0 永久选通）
  // 电平数组初值 = LogicStates.HI_Z (2)，保证上电全灭
  this.publishInitial(); // 发布全零帧
}
```

`onPinChange` 入口同时兼容事件对象形态（`(event: PinChangeEvent)`）与三参形态，参考 `ultrasonic/simulation.ts:144` 的兼容写法。

### 4.3 生命周期钩子清单

| 钩子 | 职责 |
|---|---|
| `onBound` | 建反查表、解析极性属性、分配/复位 `Uint8Array`、发布初始全零帧 |
| `onPinChange` | `integrateTo(atUs)` → 更新对应线电平 → 重算选通态/冲突计数 → `throttle.request()`；**禁止在热路径分配对象** |
| `onReset` | 电平数组归 HI_Z、亮度/掩码清零、`throttle.reset()`、取消 tail 链、发布全零帧 |
| `onPropertyChange(key, old, neu)` | 极性/颜色类变更即时生效（不丢积分状态）；`variant` 运行时变更不支持（引脚集静态），变更仅告警忽略 |
| `serializeState()` | 返回 `{ bright, segLevel, digLevel }`（快照/断点续跑） |
| `deserializeState(s)` | 恢复数组；`lastEdgeUs` 重置为 `ctx.system.time.nowUs()`，避免恢复瞬间巨量衰减跳变 |
| `onPowerOff / onPowerOn` | 灭帧 / 重新发布初始帧 |
| `onDestroy` | `throttle.reset()`、取消 tail 链、`super.onDestroy()` |

## 6. 详细实现规格

### 6.1 `variants.ts`：变体、引脚集与画板坐标

- 变体键：`direct_gpio_8d`（默认）、`direct_gpio_4d`、`direct_gpio_2d`、`direct_gpio_1d`；`resolveSegVariant(raw)` 用 `normalizeVariantKey` 归一化，无法识别回落 8d。
- 每个 variant 一份引脚数组（8 段 + N 位，§2.1）；`manifestFactory(variant)` 产出对应 manifest。
- `SEG_TOPOLOGIES`：仿 `led/variants.ts`，每变体含 `getPins: () => pinsFromBinderVariant('seg_display', variant)`、`pinsOverlay`、`defaultAppearanceId`。
- **画板 overlay 坐标**（元件尺寸 `width: 210, height: 96`，原点为元件左上角）：
  - 位选脚布置于**上边**（y=0），`DIG1…DIG{n}` 从左到右等距，`wireNet: 'secondary'`；
  - 段选脚布置于**下边**（y=96），`A…G,DP` 紧凑等距，`wireNet: 'primary'`；
  - `wireNet` 仅接受 `'primary'|'secondary'|'vcc'|'gnd'`——段/位分网正好配合走线引擎的成对信号线对称扇出与避让走廊；
  - 不设 `defaultConnection`（板级默认接线由 Part 2 的 wink-app/device-tree 决定）。
- `SEG_APPEARANCES`：`seg_display_8/4/2/1` 四个 appearance（`appearanceId/variant/displayName/searchAliases`，别名含 `seg`、`7seg`、`数码管`、`digital tube`）。

### 6.2 `simulation.ts`：`SegDisplayPlugin`

按 §3、§4 实现。核心私有状态：

```ts
private nDigits = 8;
private segPinOf = new Map<number, number>();  // mcuPin -> 0..7
private digPinOf = new Map<number, number>();  // mcuPin -> digit
private segLevel = new Uint8Array(8);          // LogicState，初值 HI_Z(2)
private digLevel: Uint8Array;                  // 长度 nDigits，初值 HI_Z
private bright = new Uint8Array(8 * 8);        // nDigits*8
private segMask = new Uint8Array(8);
private lastEdgeUs = 0n;
private tailGen = 0;
private staticDrive = false;
// 极性：segActiveHigh: boolean; digActiveHigh: boolean;
private throttle = createThrottlePublish({ ctx: () => this.ctx, intervalUs: 33_000n, publish: () => this.publishFrame() });
```

字形译码放在 `seg-font.ts`：`decodeSegMask(mask: number): string`，覆盖 `0-9 A b C d E F H L n o P r t U - 空格`，其余返回 `�`。

### 6.3 `definition.ts` 与 Canvas 数据通路

- 仿 `led/definition.ts`（**不是** mono_oled 的 displayFrame 通路——seg_display 不走 worker display 采集，走通用 `pluginChannels`）：

  ```ts
  function resolveBright(comp, ctx): Uint8Array | null {
    const id = resolvePluginInstanceId(comp, identity.type);
    const ch = ctx.pluginChannels?.[id];
    return ch?.bright instanceof Uint8Array ? ch.bright : null;
  }
  ```

- `canvasProps(comp, ctx)` 返回：`{ bright, segMask, text, nDigits, color, glow, brightness, label, flip }`；`worldProps` 同理（精简）。
- props schema 含 §2.2 全部属性 + `appearanceId` + `pluginInstanceId/pluginIndex`（advanced，与 mono_oled 一致的多实例定位约定）。

### 6.4 `CanvasGlyph.vue`：SVG 高保真渲染

- 结构：N 个 `<g class="seg-digit">` 横向排列；每位含 7 个带 ~8° 斜角的六边形段（polygon）+ 1 个圆形 DP。
- **辉光性能**：`<defs>` 中定义**唯一一个** `feGaussianBlur` 滤镜（或 CSS `drop-shadow`），挂在每位一个 `<g>` 层级（共 N 个），**禁止每段一个滤镜**；点亮段 `filter:url(#glow)`。
- 数据绑定：每段 `:fill` 为颜色表亮/暗成对值，`:fill-opacity` 由 `bright[d*8+s]/255 * brightness` 驱动；熄灭段保持 ~8% 透明度的暗色形体（真实数码管未点亮段可见暗轮廓），不隐藏。
- 颜色表与 `led` 插件七色对齐，每色定义 `lit`（发光色）/`dim`（暗形体色）。
- 根节点 `role="img"` 与 `:aria-label="text"`（无障碍 + 调试读数）。
- 不引入 `@wokwi/elements`（其无 7 段数码管元件）；纯 SVG + Vue。

## 8. 测试计划（`bun:test`，mock ctx，虚拟时间喂 `bigint` 时间戳）

测试风格仿 `led/__tests__/simulation.test.ts`：手工 `new SegDisplayPlugin()`，mock `ctx = { publish(), nowUs(), deferUs(), system: { log } }`，直接调 `onBind` / `onPinChange(pin, level, atUs)`。

### 8.1 基础契约

1. manifest `type==='seg_display'`、`category==='display'`、`timingModel==='event-driven'`；stateChannels 类型仅含 number/boolean/string；
2. 四个 variant 的 manifest 引脚数 = 8 + N（8d=16 / 4d=12 / 2d=10 / 1d=9，且 1d 的 DIG1 `required===false`）；
3. `manifestFactory('direct_gpio_4d')` 返回 12 脚 manifest；未知 variant 回落 8d；
4. `onBound` 后发布一次全零帧；未发任何边沿时亮度全 0（**上电 HI_Z 全灭**）。

### 8.2 静态直驱与极性矩阵

5. 共阴默认（seg high/dig low）：DIG1=LOW、A=HIGH → 位 0 的 A 段积分饱和；DIG1=HIGH → 不亮；
6. **四极性组合矩阵**（segActiveLevel × digitActiveLevel 各两种）：同一组波形按对应电平反相喂入，译码 `text` 结果一致；
7. `commonAnode=true` 预设等价于 seg=low/dig=high；显式 level 优先于预设；
8. 1d 静态：不映射 DIG1，段线电平 alone 即可点亮。

### 8.3 动态扫描（虚拟时间步进）

9. **正常 8 位扫描**：模拟 1ms/位切换（每位选通 1000µs，段码按位切换），推进 50ms 虚拟时间 → 8 位 `segMask` 全部正确、亮度 ≥ 200、`text==='12345678'`（或预置字形）；
10. **鬼影**：切位时插入 50µs "旧段码+新位"重叠窗口 → 受影响邻位错误段亮度 >0 但 `< GHOST_MAX_BRIGHT(40)`，且不进入 `segMask`（< LOGIC_THRESHOLD）；
11. **慢扫描**：10ms/位（整帧 80ms ≈12.5Hz）→ 稳态亮度显著低于用例 9（断言 <150），复现变暗；
12. **多位同时选通**：两位 DIG 同时有效 1ms → 两位亮相同段码、亮度偏暗，且 `activeDigits≥2`、warn 回调被触发（限频）；
13. **节流**：1ms 虚拟时间内灌 1000 个边沿 → `publish` 调用次数 = 1；
14. **余辉拖尾**：停止边沿后，tail defer 链使亮度在 ~200ms 虚拟时间内衰减到 0 并发布全暗帧；
15. HI_Z/CONFLICT：扫描中途把段线置 HI_Z → 对应段不点亮；CONFLICT 不点亮且产生 warn。

### 8.4 生命周期

16. `onReset` 后亮度/掩码清零、发布全零帧、tail 链取消；
17. `serializeState → deserializeState` 亮度一致，且恢复后 `lastEdgeUs` 不产生衰减跳变（推进 1ms 亮度变化连续）；
18. `onPropertyChange` 切换极性后新波形按新极性解释；运行时改 variant 被忽略且告警。

### 8.5 渲染与变体（轻量）

19. `variants.test.ts`：四变体 overlay 坐标无重叠、wireNet 分组正确、appearances 与 variant 一一对应；
20. CanvasGlyph（可选 Vue Test Utils）：给定全亮亮度矩阵 → 56+8 个段节点均为点亮不透明度；给定掩码 `'8'` 字形 → 七段全亮。

## 11. 风险、未决项与后续路线图

### 11.1 本计划内的未决项（不阻塞 M1–M4，M5 前定值）

- **8051 MCU 引脚编号映射**：unisim 中 P0.0~P0.7 / P2.0~P2.7 的抽象引脚号以 Part 2 实际 `pinMapping` 键为准；插件只依赖 `onBound` 拿到的映射，不硬编码。
- **积分常数整定**：`DECAY_TAU_US / CHARGE_RATE / LOGIC_THRESHOLD / GHOST_MAX_BRIGHT` 以 §8 用例 9–11 的断言为准在 M3 整定。

### 11.2 明确不在 Part 1 范围（路线图）

- `hc595_*` 变体（74HC595 锁存器段驱，3 线串行）、`hc138_*`（3-8 译码位选）——引脚拓扑不同，后续变体；
- **TM1637 / MAX7219 是协议芯片**（串行协议 + 内部扫描/显存），不属于 pin-level 数码管插件，应单独立插件计划（Wokwi 中亦为独立 chip 元件）；
- DAL 驱动与 codegen 集成 → Part 3；8051 裸机端到端 → Part 2。
