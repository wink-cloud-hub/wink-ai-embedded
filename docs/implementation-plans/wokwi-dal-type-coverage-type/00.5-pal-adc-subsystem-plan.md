## 1. 背景与阻塞诊断（2026-08-05 核对）

DAL 模拟外设家族被以下底层缺口阻塞，均已逐项核对代码：

1. **PAL 无 ADC API**：`pal/include/hal/pal_hal.h` 仅有 GPIO/PWM/I2C，无任何 `pal_adc_*`。
2. **资源治理无 ADC 类型**：`pal_resource.h` 枚举止于 `PAL_RESOURCE_UART_PORT=5`。
3. **Wasm 无 ADC 读通道**：`wasm_bridge.h` 只有 `js_pal_gpio_read` / `read_state`；但 PinArbiter 已有模拟通道（`setAnalogDriver`/`readAnalog→[0,1]`），退化引擎已有 `adc_noise_v`/`rc_tau_s` 与 `wink_phys_rc_lowpass`/`wink_phys_warmup_check`——**通道 3 的"最后一公里"只差 PAL ADC 与桥导入**。
4. **Role 缺失**：`codegen/roles/` 有 7 个 role，无 `analog_input.yaml`（但其契约已在 Role SSOT 定稿）。

> 本计划是 ADR-0057 的**执行排期**，不重新做技术决策。下文每条标注对应 ADR 决策编号。

## 2. PAL ADC 公共 API（ADR 决策 1）

新建 `wink-micro-os/pal/include/hal/pal_adc.h`：POD 配置 + 命名式静态 API（ADR-0004），全函数返回 `wink_status_t`（ADR-0001），`WINK_WARN_UNUSED_RESULT`。

```c
typedef uint8_t pal_adc_channel_t;   /* [0, PAL_ADC_CHANNELS)，默认 16，可 -D 覆盖 */

typedef struct {
    wink_pin_t   pin;              /* int16_t 语义，兼容 NC(-1) */
    uint16_t     full_scale_mv;    /* 0 = 平台默认（ESP32≈3100, wasm/host=3300） */
    uint8_t      resolution_bits;  /* 0 = 平台默认（12） */
} pal_adc_config_t;

wink_status_t pal_adc_init(pal_adc_channel_t ch, const pal_adc_config_t *cfg);
void          pal_adc_deinit(pal_adc_channel_t ch);

wink_status_t pal_adc_channel_pin(pal_adc_channel_t ch, wink_pin_t *out_pin); /* 正向 */
wink_status_t pal_adc_pin_channel(wink_pin_t pin, pal_adc_channel_t *out_ch); /* 反向 */

wink_status_t pal_adc_read_raw(pal_adc_channel_t ch, uint16_t *out_raw);
wink_status_t pal_adc_read_mv (pal_adc_channel_t ch, uint16_t *out_mv);
wink_status_t pal_adc_full_scale_mv(pal_adc_channel_t ch, uint16_t *out_mv);
```

**关键契约（ADR §1）：**

- **逻辑通道句柄**：上层只持有 `pal_adc_channel_t`（0..N-1）。`pal_adc_init(ch, cfg)` 内部按 `cfg->pin` 查 board 元数据，映射到目标平台物理 ADC 单元/通道（如 ESP32 ADC1_CH0），上层不感知硬件通道重叠。
- **采样时刻一致性**：per-channel 状态缓存 `last_raw` + `last_sample_us`。`read_raw` 触发一次物理采样并刷新缓存；`read_mv` 复用同一缓存 Raw 做校准换算，**保证 raw 与 mv 时刻一致且不重复触发采样**。`read_mv` 必须优先复用有效缓存 Raw，严禁在 `read_mv` 内部二次触发物理/退化采样间隔检查（避免在同一 tick 内调 raw 再调 mv 误报 `WINK_ERR_TIMEOUT`）。
- **范围界定：片上 ADC ≤ 16-bit**。本头文件只服务 MCU 内置 ADC（`uint16_t` 不溢出）。HX711（24-bit ΔΣ）等外部高精度 ADC **不进入** `pal_adc.h`，走专用 GPIO/SPI Bit-bang 驱动（`load_cell` DAL 自行实现）。
- **不导出 `pal_adc_atten_t`**。衰减是 esp32 内部细节：按 `full_scale_mv` 选最接近的硬件 atten + eFuse 曲线校准。App 需要非标准档时走 target-private `<pal_adc_esp32.h>`，不污染公共头。
- **阻塞语义 + STRICT_NONBLOCKING 门控（已澄清）**：`pal_adc_read_raw/mv` 是**单次 oneshot 转换**，在 esp32 上为 µs 级忙等轮询转换完成位（短时阻塞），不是连续采样/DMA。**严格照搬 `pal_hal.h` 中 `pal_i2c_transfer`/`pal_gpio_pulse_in` 的既有模式**：在 `pal_adc.h` 用 `#ifndef WINK_STRICT_NONBLOCKING ... #endif` 包住这两个读函数，并标注 `WINK_BLOCKING`（文档注明"最坏 = 一次转换时间，µs 级"）。wasm/host 实现同步即时返回也仍受同门控（与 i2c 一致，按 API 语义分类而非按实际耗时）。连续采样 + PWM 硬件触发属 ADR-0047 `pal_hwtimer`，不在本计划。
  > 后果：在 `WINK_STRICT_NONBLOCKING` 严格构建下，模拟传感器 DAL 与 i2c 传感器一样不能直接调 ADC read，须经非阻塞状态机/异步路径——这是 ADR-0017 的既定约束，不是新限制。
- `pal_adc_init` 对 `cfg==NULL` / 越界 channel / pin 无 ADC 能力返回 `WINK_ERR_INVALID_ARG`；重复 init 同 channel 返回 `WINK_ERR_ALREADY_INITIALIZED`（不隐式 deinit，对齐 DAL-L-004）。未 init 读返回 `WINK_ERR_NOT_INITIALIZED`。

## 3. 资源治理（ADR 决策 2）

`pal_resource_type_t` 增 `PAL_RESOURCE_ADC_CHANNEL = 6`（host/esp32 资源表扩容；wasm 仍 no-op）。

- **Claim 主体是 DAL，不是 PAL**（对齐既有 `02-pal §4.1` 原则，2026-07-02 落地）：`pal_adc_init` **内部不调用 `pal_resource_claim`**，只做硬件配置——与 `pal_gpio_init`/`pal_pwm_init_ex` 自身不 claim、由 `dal_button`/`dal_rc_servo` claim 的现状一致。否则 PAL 固定 owner 会与 DAL 的 device-owner claim 二次冲突恒返 BUSY，并掩盖冲突者身份。
- 消费 ADC 的 **DAL 驱动**（`dal_analog_knob`/`dal_analog_sensor` 等，在 #1/#5/#18/#19 子计划）在 `pal_adc_init` 前后负责：同时 claim `PAL_RESOURCE_ADC_CHANNEL, ch` 与 `PAL_RESOURCE_GPIO_PIN, pin`（同一 `cfg->owner`），任一失败回滚；deinit 同步 release 两者。ADC 脚与数字脚互斥的跨子系统冲突由此被既有资源表拦截。
- 本前置计划交付 PAL 能力与 `PAL_RESOURCE_ADC_CHANNEL` 枚举；具体 DAL claim 代码在各外设子计划落地（T3 单测可直接调 `pal_resource_claim` 验证冲突语义）。

> **现状注记**：既有 PWM 路径（`dal_rc_servo.c:60`）当前只 claim PWM_CHANNEL、未 claim 对应 GPIO pin。本计划要求 ADC DAL 做更严格的双重 claim（ADC 脚与数字脚互斥是真实冲突）。PWM 是否补齐 GPIO_PIN claim 是独立一致性整改，不在本计划范围，记 follow-up。

## 4. 三 Target 差异化实现

> 文件命名/位置遵循现状：esp32 与 host 平铺在 `targets/<t>/`（如 `pal_hal_gpio_esp32.c`、`pal_hal_host.c`），**没有 `hal/` 子目录**；wasm 为 `targets/wasm/pal_wasm_adc.c`。三个 target 的 `CMakeLists.txt` 均为**显式源文件列表**（非 glob），新增 `.c` 必须手动注册，esp32 的 CMake 有**两处**源列表都要加。

### 4.1 ESP32（`targets/esp32/pal_hal_adc_esp32.c`）— ADR 决策 4

> ⚠️ **强制前置：编码前必须先通读 ESP-IDF v6.0.1 官方 ADC 文档，再动手。** 不要凭 v5 经验或网络博客写代码（ADC 校准 API 在 v5→v6 有演进，凭记忆写易触发 implicit-declaration 编译错误或资源泄漏）。
>
> **官方文档路径（本机）：** `D:\software\embedded\esp\v6.0.1\esp-idf\docs\`
>
> | 必读文档（zh_CN/en 任选） | 覆盖内容 |
> |---|---|
> | `api-reference/peripherals/adc/adc_oneshot.rst` | oneshot 模式：unit 句柄、channel 配置（atten/bitwidth）、单次阻塞读、io↔channel 映射、句柄删除、ADC2/Wi-Fi 限制 |
> | `api-reference/peripherals/adc/adc_calibration.rst` | 校准 scheme 选型（curve/line fitting）、eFuse 前置、`raw_to_voltage`、create/delete 配对、各芯片支持矩阵 |
> | `api-reference/peripherals/adc/continuous_*.rst` | **仅需了解**（本计划用 oneshot，不用 continuous/DMA，continuous 属 ADR-0047 `pal_hwtimer` 范畴） |
>
> 同时以**头文件为准**核对符号：`components/esp_adc/include/esp_adc/adc_oneshot.h`、`adc_cali.h`、`adc_cali_scheme.h`、`hal/adc_types.h`。文档与头冲突时以头文件为准（对齐 ABI 文档"签名以头为准"惯例）。

**工具链基线 ESP-IDF v6.0.1**（不是 v5.x）。基于已核对的 v6.0.1 头文件，实现要点：

- **pin→(unit,channel) 用官方 API，禁止自造硬编码表**：
  `adc_oneshot_io_to_channel(int io_num, adc_unit_t *unit_id, adc_channel_t *channel)` 已由 IDF 提供，直接用 `cfg->pin` 解析。反向用 `adc_oneshot_channel_to_io`。这同时天然支持 ESP32/S3/C3 变体（各芯片映射不同，IDF 内部处理），与"不在代码写死全量 ESP32 表"的决策一致。正向 `channel→pin` 由 init 写入 per-channel 状态保存，不需要额外的 weak pin-map（见 §6）。
- **oneshot 生命周期与多任务安全**：`adc_oneshot_new_unit(&init_cfg, &unit)` → 每通道 `adc_oneshot_config_channel(unit, ch, &chan_cfg)`（atten + bitwidth）→ `adc_oneshot_read(unit, ch, &raw)` → `adc_oneshot_del_unit(unit)`。多 channel 共享同一 unit 句柄时做**引用计数**，最后一个 deinit 才 `del_unit`。多任务并发调 init/deinit 时，Unit 句柄数组与引用计数由静态互斥保护（如 `portENTER_CRITICAL` 或 static Mutex）。
- **atten 由 `full_scale_mv` 选择**：用 `adc_atten_t`（优先使用 `ADC_ATTEN_DB_12`，预编译宏回退兼容 `ADC_ATTEN_DB_11`，定义于 `hal/adc_types.h`）选最接近请求满量程的档；`ADC_ATTEN_DB_12` ≈ 3.1V（不是精确 3.3V，文档明确；v6.0.1 推荐 12dB，用 `#ifndef ADC_ATTEN_DB_12` 防 `-Werror` 警告）。`resolution_bits` 映射到 oneshot chan_cfg 的 bitwidth（默认 12-bit）。
- **校准（输出 mV）**：
  1. 先 `adc_cali_check_scheme(&scheme_mask)` 判断当前芯片支持哪些 scheme；
  2. 按 `adc_cali_curve_fitting_config_t`（atten/unit/chan/bitwidth）调 `adc_cali_create_scheme_curve_fitting(&cfg, &cali)`，不支持则回退 line fitting；两个 create 分别由 `ADC_CALI_SCHEME_CURVE_FITTING_SUPPORTED` / `LINE_FITTING_SUPPORTED` 宏门控，**必须用 `#if` 包住**，否则不支持该 scheme 的芯片编译失败；
  3. 读电压用 `adc_cali_raw_to_voltage(cali, raw, &mv)`（或 `adc_oneshot_get_calibrated_result`）；
  4. **`init` 创建的 `adc_cali_handle_t`，`deinit` 必须配对调用 `adc_cali_delete_scheme_curve_fitting/line_fitting`**，防止反复 init/deinit 泄漏 ESP-IDF 堆。
- **ADC2/Wi-Fi 限制**：官方文档明确 ADC2 部分通道在 Wi-Fi/BLE 启用后不可用。本计划**不在运行时探测 Wi-Fi**（ADR 决策 3）；该约束由 codegen 静态门禁拦截（§7）。若运行时 oneshot 读返回 ESP_ERR_INVALID_STATE 等硬件不支持错误，映射为 `WINK_ERR_UNSUPPORTED`。
- **错误映射**：所有 `esp_err_t != ESP_OK` 映射到精确 `wink_status_t`（INVALID_ARG / BUSY / HARDWARE / UNSUPPORTED），不吞错、不一律 `WINK_ERR_IO`。
- **不在 ISR 上下文读 ADC**：oneshot read 是阻塞 API，调用上下文由 DAL/App 保证（task 上下文）；与 `pal_adc_read_*` 非阻塞 oneshot 语义一致。

### 4.2 Wasm（`targets/wasm/pal_wasm_adc.c` + `wasm_bridge.h`）— ADR 决策 3

**桥接导入（新增，唯一）：**

```c
/* 返回 PinArbiter.readAnalog(pin) 的归一化值 [0,1]。不返回 mV。 */
extern float js_pal_adc_read_norm(uint16_t pin);
```

- **不新增** `js_pal_adc_read_mv`。JS 侧（`WasmPhysicalBridge`/imports 实现）读 `PinArbiter.readAnalog(pin)`，电位器等元件已通过 `setAnalogDriver` 写入归一化值。JS 不做 mV 换算、不知满量程。
- **C 侧读路径**（通道 3 同源换算留在 C）：
  1. `pal_adc_channel_pin(ch, &pin)` 取物理脚；
  2. `norm = js_pal_adc_read_norm(pin)`（理想物理源）；
  3. **经退化引擎**：`wink_phys_rc_lowpass(&rc_ctx[ch], norm, now_us, s_faults.rc_tau_s, s_faults.adc_noise_v, &seed[ch])` → 含噪/低通 norm；
  4. `wink_phys_warmup_check(now_us, power_on_us[ch], s_faults.warmup_us, s_faults.sample_interval_us, &last_sample_us[ch])`：预热内 `WINK_ERR_BUSY`，采样过近 `WINK_ERR_TIMEOUT`；
  5. C 内换算：`raw = (uint16_t)(norm_filt * ((1u<<bits)-1))`、`mv = (uint16_t)(norm_filt * full_scale_mv)`，写 `last_raw` 缓存。
- **Per-Channel 独立 PRNG（ADR §3）**：per-channel 状态数组按 `ch`（0..PAL_ADC_CHANNELS-1）索引，**不是 pin**（channel 是 PAL 稳定句柄；pin 只是 init 时的映射）。每通道静态 `uint32_t seed[ch]` 由 `hash(pin)` 在 init 时确定性派生一次（不消费全局 `s_prng`），把 ADC 噪声随机数消耗隔离在通道内，**不扰动非模拟外设的 golden 向量**。这是对 ADR-0009 §7"全局单 PRNG"的有意演进（该节已预留 per-id 子流派生为 Planned）。
- **退化配置访问（复用现有，勿新建）**：`adc_noise_v`/`rc_tau_s`/`warmup_us`/`sample_interval_us` 是 `pal_wasm_physical.c` 的 `static s_faults`。`pal_wasm_adc.c` 直接 `#include "pal_wasm_internal.h"`（**该头文件已存在，勿新建**），调用其中已有的 `wink_sim_faults_t *pal_wasm_get_faults_ref(void);` 只读读取配置（指针可写，但 ADC 代码须自律只读，不修改它）。**不新增 getter、不重复 setter**（前端仍经既有 `pal_wasm_set_adc_noise_v` 等配置）。Wave3 把 faults 改为 per-domain 后该 helper 会一并迁移（头文件已有 TODO 标注）。
- per-channel RC ctx / seed / power_on_us / last_sample_us 放静态 BSS，按 `PAL_ADC_CHANNELS` 定长，越界/未 init 通道直通返回错误，范式同 `pal_wasm_physical.c`。
- 新 import 照搬既有 `js_pal_gpio_read_state` 的声明与 safeWrap 接线模式（见 `wasm_bridge.h` 与 bridge-abi ABI #6），返回 float 不需要 Asyncify（同步 import）。
- **TS 侧同步（强制工序，漏一项 CI 即红）**：
  1. `packages/unisim/src/unisim/types/wasm/imports.ts` 的 `WasmImports` 增 `js_pal_adc_read_norm`；
  2. `createUnisimImports` / `installUnisimBridge` 接线，实现内调 `pinArbiter.readAnalog(pin)`，并在 safeWrap 中增加浮点数边界防御：`Number.isFinite(val) ? Math.max(0, Math.min(1, val)) : 0.0`（遵循 WASM ABI 契约 #2 防范 NaN/Infinity 污染 WASM C 侧滤波）；
  3. `ssotAlignment.test.ts` 解析 `wasm_bridge.h` 自动比对（无需手改，但本地必须跑过）；
  4. bump `PAL_WASM_ABI_HASH`（**C 与 TS 各一份**）。
- **Golden 后果**：ADC 新路径不碰全局 PRNG，故既有非模拟 golden 不受影响；但新增的 ADC 自身 golden vector 与 PRNG 派生 hash 绑定，hash 算法变更须重基并在 PR 记录。

### 4.3 Host（`targets/host/pal_hal_adc_host.c`）— ADR 决策 5

- 确定性注入 API：
  ```c
  void pal_host_adc_inject_raw(pal_adc_channel_t ch, uint16_t raw);
  void pal_host_adc_inject_mv (pal_adc_channel_t ch, uint16_t mv);
  ```
  注入后 `read_raw`/`read_mv` 一致返回（按 `full_scale_mv`/`resolution_bits` 互算填充缓存），供 CTest 确定断言。不依赖 PinArbiter/JS。
- host 也编译 `wink_sim_physical` 算法库；是否在 host ADC 读路径叠加 RC/噪声由测试用例显式配置（默认 faults=0 直通，符合"全 0 = 理想"）。

### 4.4 Baremetal：当前不适用（未来约束）

- 当前仓库**没有 `targets/baremetal/` HAL target**（`TARGET_PLATFORM` 仅 wasm/host/esp32；baremetal 只有 `osal/baremetal/pal_osal_baremetal.c`）。因此本计划**不产出** baremetal ADC 文件，"三 target"即完整构建矩阵。
- ADR-0057 中"baremetal stub"是面向**将来**新增 baremetal HAL target 的约束，届时：全函数返回 `WINK_ERR_UNSUPPORTED`；stub 不得引用 `wink_sim_physical`/`pal_wasm_physical` 符号（对齐 physical-degradation §9 零污染 grep）；CMake 显式枚举源文件。记为 follow-up，不阻塞本计划。

## 5. Role 契约落地（ADR 决策 7 / Role SSOT §3.2-5）

新建 `wink-micro-os/codegen/roles/analog_input.yaml`，严格遵循真实 schema 1.1 与 Role SSOT 的动词集，**不自创 verb**：

```yaml
codegen_schema: "1.1"
id: analog_input
verbs:
  - id: read_promille
    error_class: convenience     # -> uint16_t，归一化 [0,1000]
  - id: read_mv
    error_class: convenience     # -> uint16_t，引脚电压 mV
  - id: read_promille_status
    error_class: normal          # -> wink_status_t，out 指针诚实读
```

- `read_promille` 由 **DAL**（非 role 模板直接）调 PAL `read_raw` 换算：`raw * 1000 / ((1<<bits)-1)`。C 侧强转为 `uint32_t` 乘法防 16 位溢出（`4095 * 1000 = 4,095,000` 必须提升为 `uint32_t` 算）：`(uint16_t)(((uint32_t)raw * 1000U) / ((1U << bits) - 1U))` 并在边界做 `clamp(0, 1000)`。role 模板仅做单行内联转发，不含业务逻辑（Role SSOT §5：≤3 行展开等效）。
- 映射 type 按 Role SSOT §4：`analog_knob` / `analog_sensor` / `load_cell` / `heart_rate` 的 `default_role = analog_input`（`encoder` 备选）。
- 业务物理解释（温度/光照/BPM/重量）**不在本 role**：由 App/BAL 基于 `read_mv` 换算，或由 `environment_sensor`/`motion_sensor` 等专用 role 承担。

> Role SSOT 明确"role 是 codegen 内联 facade，不是 BAL"。各 DAL type（`analog_knob`/`analog_sensor` 等）需在各自 `codegen/drivers/<type>.yaml` 的 `role_bindings` 提供 `template`，本计划只交付 role 契约本身；DAL 驱动模板由 #1/#5/#18/#19 子计划各自落地。

## 6. Board 元数据（ADR 决策 6）

在真实路径 `wink-tools/tools/codegen/boards/*.json`（**不是** `wink-micro-os/boards/`，该目录不存在）现有结构内增 `adc` 段：

```jsonc
"adc": {
  "pins": {
    "36": { "channel": 0, "unit": 1 },
    "39": { "channel": 3, "unit": 1 },
    "25": { "channel": 8, "unit": 2, "wifi_conflict": true }
    // ...仅列该 board 实际引出且可用的脚，不伪造全量
  },
  "default_full_scale_mv": 3100,
  "default_resolution_bits": 12
}
```

- 不同芯片变体（ESP32 / S3 / C3）通道映射不同，各自 board json 表达，**代码不写死"全量 ESP32 表"**。
- **运行时映射机制（已简化）**：board json 是 codegen 期 SSOT（供 §7 静态门禁）。运行时**不需要额外的 ADC weak pin-map**：
  - 反向 `pin→(unit, channel)`：esp32 直接用 IDF 官方 `adc_oneshot_io_to_channel()`（已天然支持 S3/C3 变体）；
  - 正向 `channel→pin`：由 `pal_adc_init` 写入 per-channel 状态结构体保存（`pal_adc_channel_pin` 从状态读），不依赖全局表。
  - 这比 PWM/I2C 的 `pal_pwm_pin_map` weak 表更简单——ADC 有 IDF 官方映射，无需自造表。

## 7. Codegen ADC 静态门禁（ADR 决策 6，新增能力）

这是**新增 codegen 能力**，单列任务，不得隐含在"改 JSON"里。

### 7.1 `system.connectivity` 系统能力段（新增 schema）

ADC2 冲突只与"**SoC 内置 Wi-Fi/BLE radio 是否启用**"有关，与外部 Wi-Fi 模组（ESP8266 / ESP32-C3 AT 模组，经 UART/SPI 挂载，是 comm 外设，不占用主控 ADC2）**无关**。因此在 `wink-app.json` 引入一个正交于 `devices` 的系统能力段：

```jsonc
{
  "app_name": "iot_sensor",
  "board": "esp32_devkitc",
  "system": {
    "connectivity": { "wifi": true, "ble": false }   // 均可选，默认 false
  },
  "devices": { ... }
}
```

- **语义**：声明本 App 启用主控 SoC 内置 radio 协议栈。`wifi: true` 表示会初始化 SoC Wi-Fi（触发 ADC2 限制）；外部 Wi-Fi 模块在 `devices` 里作为 comm type（如 `wifi_module`/`at_modem`，走 UART），**不**置位此字段，也不触发 ADC2 门禁。
- **board 有 Wi-Fi 硬件 ≠ App 启用 Wi-Fi**：信号必须来自 App 侧声明（纯本地 App 即便跑在 esp32_devkitc 上也可用 ADC2）。
- **预留 `ble`**：ESP32 ADC2 同样受 BLE 影响，门禁可一并判断 `wifi || ble`，将来零结构改动。
- codegen 的 top-level schema 校验（`app_codegen.py::validate_top_level` 与 `yaml_schema.py` 白名单）增认可选 `system.connectivity`（及其子项 `wifi`/`ble`），防止 fail-closed 规则将 `system` 误判为非法顶级节点，非法字段/类型 Fail-Loud。

### 7.2 门禁规则

1. **读取点**：设备树校验阶段（`_load_board_config` 成功后、遍历 devices 时，用现有 `_die()` 报错）读 board json 的 `adc.pins` 与 app 的 `system.connectivity`。
2. **规则**：
   - **R1 引脚能力**：`analog_input` 类外设所接 `gpio_pin` 在该 board `adc.pins` 缺失 → **Fail-Loud**（该脚无 ADC 能力）；
   - **R2 ADC2/radio 冲突**：所接脚 `wifi_conflict: true` 且 `system.connectivity.wifi == true`（或 `ble == true`）→ **Fail-Loud**；
   - **R3（可选增强）**：同一 ADC channel 被两个外设实例声明 → 报错（运行时虽有 pal_resource 双 claim，生成期拦截更早）。
3. **报错信息**：须指明实例 id、引脚、所属 ADC unit、冲突原因与修复建议（如"GPIO25 属 ADC2，在 system.connectivity.wifi=true 时不可用；改用 ADC1 引脚或关闭 Wi-Fi"）。
4. **测试**：在 `wink-tools/tools/codegen/tests/` 增加正反用例——合法 ADC1 脚通过；非 ADC 脚失败（R1）；ADC2 脚无 Wi-Fi 通过、ADC2 脚 + `connectivity.wifi=true` 失败（R2）；外部 UART Wi-Fi 模组 + ADC2 脚**通过**（证明不与内置 radio 混淆）。

> 这把 ADC2/Wi-Fi 这一**静态拓扑约束**在生成期拦截，运行时 PAL 保持对网络栈无知（ADR 决策 3）。

## 10. 风险与备注

| 风险 | 缓解 |
|---|---|
| ESP-IDF v6 校准 API 名称与 v5 文档不一致 | T5 编码前先 grep v6 头文件核对 scheme 创建/删除函数名；以编译 0 error 为准 |
| ESP-IDF v6 衰减宏 `ADC_ATTEN_DB_11` 弃用警告 | 使用 `ADC_ATTEN_DB_12`，并通过 `#ifndef ADC_ATTEN_DB_12` 预编译宏向后兼容 `ADC_ATTEN_DB_11`，确保在 `-Werror` 构建下零警告 |
| `read_promille` 乘法 16 位整数溢出 (`4095*1000`) | C 换算强制提升为 `(uint32_t)raw * 1000U` 运算并做 `clamp(0, 1000)` |
| WASM `read_mv` 二次触发退化间隔校验导致超时误报 | `read_mv` 必须优先复用 `last_raw` / `last_sample_us` 缓存，禁止在 `read_mv` 内部重新调用预热/采样间隔检查 |
| TS 侧 `pinArbiter.readAnalog` 返回 NaN/Infinity 污染 WASM 滤波 | TS 导入包装层 safeWrap 加 `Number.isFinite(val) ? Math.max(0, Math.min(1, val)) : 0.0` 防护 |
| `system.connectivity` 属性被 codegen top-level schema 拒收 | T10 在 `app_codegen.py::validate_top_level` 与 `yaml_schema.py` 顶级节点白名单中增加 `system` 节点 |
| `s_faults` 是 `pal_wasm_physical.c` static，ADC 读不到 | T7 复用已存在的 `pal_wasm_internal.h::pal_wasm_get_faults_ref()`（只读）；不新增 getter、不重复 setter；不破坏既有前端配置路径 |
| ADC RC 作用在归一化 float 上，raw/mv 饱和 | 换算后 clamp 到 `(1<<bits)-1`/`full_scale_mv`，Debug 可 warn，Release 不回卷 |
| board ADC 引脚表不全/芯片变体差异 | 仅列实际引出脚；缺脚由 codegen 门禁 Fail-Loud；变体各自 json |
| Role 模板由 DAL 子计划提供，本计划只交付 role 契约 | T8 验收只校验 yaml 被 codegen 识别；端到端 `{instance}_read_promille` 由 #1 验证 |
| 既有 lint 历史 error 干扰"新代码零 error"判定 | **`--baseline` 已实现并端到端验证（commit 69dcb36）**：用 `--format json --output b.json` 固化存量，后续带 `--baseline b.json` 只报新增、退出码随之变化。本计划开工前先固化 baseline；注意重新生成基线时**不带** `--baseline`（工具已对 `--baseline`+`--output 同一文件` 报错拒绝）；另可对新增 PAL 文件用 `--paths` 增量扫描做双重保险 |
| 新增 `.c` 忘记注册 CMake（非 glob，esp32 有两处源列表） | T5 显式列出三处 CMake 注册点；注册后用三 target 全构建验证链接无未定义符号 |
| `pal_adc.h` 新建但未加入 `pal.h` 伞头，内核组件 include "pal.h" 看不到 | T1 把 `#include "hal/pal_adc.h"` 加入 `pal.h` |
| esp32 ADC read 的阻塞语义与 ADR-0017 非阻塞契约冲突 | 公共头标 `WINK_BLOCKING`（µs 级 oneshot），与 `pal_i2c_transfer`/`pal_gpio_pulse_in` 同处理；不放进 WINK_STRICT_NONBLOCKING |
| `system.connectivity` 是新增 app schema，与现有字段冲突或被 codegen 拒绝 | T10 在 `validate_top_level` 显式加白名单；先写 schema 单测；回写 `wink-app-json-guide.md`，避免它成为未文档化的隐式字段 |
| 外部 UART Wi-Fi 模组被误判为"SoC Wi-Fi"导致 ADC2 误拦 | 门禁只看 `system.connectivity.wifi`（App 显式声明的内置 radio），不扫 devices 里的 comm 模组；T10 含专门正反用例 |
