# 测试策略（范式无关 · 虚实同源的兑现）

> 适用范围：两种架构风格共用。本项目（wink-micro-os）的命门是「**仿真即真机，一份源码两 target**」。
> 本文件回答：这套架构下**测什么、在哪测、怎么测**——测试策略与 [realtime-hardware.md](./realtime-hardware.md)
> 的 `#ifdef SIMULATION` 收窄互为表里。

---

## 核心论点：收窄 bypass → 共享层天然可在 host 单测

ADR-0003 要求 `#ifdef SIMULATION` **只旁路最低层物理信号源**，协议解析 + CRC + 错误检测 + 物理量
换算 + 状态机在仿真与真机间**共享**（见 [realtime-hardware.md](./realtime-hardware.md)）。

这带来一个直接结论：

> **凡是「共享层」代码，都能在 host / Wasm 构建上做单测——因为它们不依赖真机寄存器。**

把 bypass 放得越靠下（ADR-0002 item 4），被 host 单测覆盖的代码就越多。**收窄 bypass 既是仿真保真
要求，也是可测性红利**——二者同源。

---

## 本项目版测试金字塔

```
        ┌───────────┐
        │    HIL    │  真机冒烟：端到端行为、时序、DMA/中断真实路径（少量、慢、贵）
        ├───────────┤
        │ host 集成  │  模块组装：DAL+PAL stub，验调用链/状态机/错误恢复（中量）
        ├───────────┤
        │ host 单测  │  共享层：协议帧/CRC/换算/滤波/错误判定/状态转移（大量、快、确定性）
        └───────────┘
```

- **底座最大**：host 单测覆盖所有「不碰寄存器」的逻辑——这是双 target 架构的最大回报。
- **HIL 最少但不可省**：寄存器时序、中断优先级、DMA/D-Cache 这些**只能**在真机验（见下「不测什么」）。

## host 单测：测什么 / 不测什么

### ✅ 测（共享层，确定性、无硬件）

| 对象 | 怎么测 |
|------|--------|
| 协议帧解析（chigo-micro CMD/STATE/PARAM 帧） | 构造字节流 → 解析 → 断言字段；含截断/超长/CRC 错帧 |
| CRC16 / 校验和 | 已知向量 + 边界（空、单字节、最大长度） |
| 物理量换算（echo 时序→距离、PWM→角度） | 纯函数，喂边界值 |
| 滤波 / 状态机转移 | 表驱动转移直接测（静态分发下状态表是数据，易测） |
| 错误码传播 / 降级逻辑 | 注入失败 → 断言正确码 + 资源已回滚 |

> 静态分发的**可测性红利**：器件是 POD，无虚表、无运行期注册——单测里直接 `{ .field = ... }`
> 构造一个实例就能测，**不需要 mock 框架去桩掉一整套 ops 表**。这是静态分发相对运行期多态的
> 隐性胜利（静态分发范式特有；见所在 skill 的架构文档）。

### ❌ 不在 host 测（只能 HIL / 真机）

- 寄存器读改写、引脚复用、外设时钟（被 bypass 的最低层）。
- 中断优先级 / `configMAX_SYSCALL_INTERRUPT_PRIORITY` 实际行为（[concurrency.md](./concurrency.md)）。
- DMA 圆形 + D-Cache 失效时序（Cortex-M7）。
- esp_timer 1kHz PID 的真实抖动 / 看门狗实际超时窗口。

> 这些不 host 测，但**必须在 HIL 覆盖**——不要因为「单测绿了」就假设真机也对。

## 帧解析器 fuzzing（高价值专项）

协议帧解析器是**无界输入面**——`memory-safety.md` 禁 `strcpy/sprintf` 的根因。单测的固定向量
覆盖不到畸形输入，应对解析器做 fuzzing：

- 喂随机/半结构突变字节流，断言「永不越界、永不崩溃、长度校验先于解析」。
- property-based：对所有长度 `0..MAX`，解析要么成功要么返回明确错误码，**绝不内存越界**。
- 用 libFuzzer / AFL 跑 host 构建（解析器是纯函数，天然可 fuzz）。

> 这是把「缓冲区溢出防护」（[memory-safety.md](./memory-safety.md)）从规则变成证据的手段。

## HIL 验证硬件路径（Hardware-In-the-Loop）

真机/目标板上的端到端冒烟，覆盖 host 测不到的部分：

| 验证项 | 手段 |
|--------|------|
| DMA UART 变长接收 | 发真实帧 → 断言环形缓冲内容 + Idle-Line 触发 |
| 中断优先级方案 | 制造高负载中断 → 断言 RTOS API 调用不崩 |
| 看门狗 | 故意阻塞 → 断言复位（见 [realtime-hardware.md](./realtime-hardware.md) 看门狗设计原语） |
| PID 1kHz 抖动 | 示波器/逻辑分析仪测回调周期 |

> HIL 不追求覆盖率，追求**覆盖 host 盲区**。频率低、自动化程度按硬件预算定。

## 工具链建议

| 层 | 工具 |
|----|------|
| host 单测 | **Unity** / **cmock**（C 原生、嵌入式主流、与静态分发 POD 契合）；或项目已有框架 |
| fuzzing | libFuzzer / AFL（host 构建） |
| 覆盖率 | `gcov` / `llvm-cov`，CI 门禁共享层覆盖率阈值 |
| HIL | pytest + 串口/逻辑分析仪桥接 |

> 优先复用项目既有测试框架，**不要引入新依赖**——先搜现有用法（见所在 skill 的上下文感知编码指引）。
