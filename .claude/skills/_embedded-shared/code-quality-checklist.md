## 1. 错误码与错误处理

📚 **对应详细规范：** [`error-codes.md`](./error-codes.md)

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 1.1 | | 所有可能失败的函数返回 wink_status_t（0=成功，负数=错误） |
| 1.2 | | **禁用 if (status)**，必须用 if (status < 0) 或 if (status != WINK_OK) |
| 1.3 | | 所有返回 wink_status_t 的 API 标记 WINK_WARN_UNUSED_RESULT |
| 1.4 | | 每层要么处理错误，要么向上传播，**绝不静默吞掉** |
| 1.5 | | 初始化链失败时，按相反顺序 deinit 已成功初始化的资源 |
| 1.6 | | 错误码分段语义正确：-1~-11 通用、-20~-29 功能安全、-30~-49 致命、-50~-59 降级 |
| 1.7 | | 每个模块提供 module_err_to_string() 表驱动错误码转字符串函数 |
| 1.8 | | 错误码包含模块来源标记（可选：status | (MODULE_ID << 24)） |
| 1.9 | | 断言抓内部契约（程序员错误），外部输入用运行时校验 + 错误码 |
| 1.10 | | 无 bool 返回 + float 哨兵值的反模式 |

## 2. Clean Code 与代码风格

📚 **对应详细规范：** [`clean-code.md`](./clean-code.md)

### 2.1 硬性限制

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 2.1.1 | | 行宽 ≤ 80 列 |
| 2.1.2 | | 函数 ≤ 80 行 |
| 2.1.3 | | 嵌套深度 ≤ 4 层 |
| 2.1.4 | | 函数参数 ≤ 5 个（更多用配置结构体） |
| 2.1.5 | | 无死代码 / 注释掉的代码 |
| 2.1.6 | | 无未使用的符号 |

### 2.2 命名约定

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 2.2.1 | | 宏 / 常量：全大写蛇形（MAX_RETRY_COUNT） |
| 2.2.2 | | 类型：snake_case + _t（motor_driver_t） |
| 2.2.3 | | 函数：模块_动作()（motor_driver_set_outputs） |
| 2.2.4 | | 局部变量 / 结构体成员：小写蛇形 |
| 2.2.5 | | 枚举值：全大写或前缀_名称 |
| 2.2.6 | | 文件级 static 变量：s_ 前缀 |
| 2.2.7 | | 全局变量：g_ 前缀 |
| 2.2.8 | | 布尔变量：is_ / has_ / can_ / should_ 前缀 |
| 2.2.9 | | 函数指针 typedef：*_fn 后缀 |

### 2.3 编码规范

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 2.3.1 | | 无魔法数字（除 NULL、1 和明显布尔值外） |
| 2.3.2 | | 宏定义的值用括号包裹：#define FOO (42U) |
| 2.3.3 | | 无符号常量使用 U 后缀，大型常量用 UL / ULL |
| 2.3.4 | | 枚举使用固定宽度存储类型：typedef uint8_t xxx_state_t; |
| 2.3.5 | | 访问器函数（getter/setter）使用 static inline |
| 2.3.6 | | 小于 5 行的热路径函数使用 static inline |
| 2.3.7 | | .h 中 static inline 加 __attribute__((always_inline)) |

### 2.4 头文件规范

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 2.4.1 | | 每个头文件有保护宏，格式 MODULE_NAME_H |
| 2.4.2 | | 头文件自包含（可独立编译） |
| 2.4.3 | | 包含路径与项目其他文件一致 |
| 2.4.4 | | 包含顺序正确：对应头文件 → 平台头 → PAL/DAL → 模块 → 标准库 |

### 2.5 函数设计

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 2.5.1 | | 单一职责（SRP）：函数只做一件事 |
| 2.5.2 | | 抽象层级一致：高层编排与裸寄存器操作不混在同一函数 |
| 2.5.3 | | 命令-查询分离（CQS）：函数要么执行动作，要么返回信息 |
| 2.5.4 | | 无副作用：validate_xxx 不偷偷修改全局状态或写硬件 |
| 2.5.5 | | 指针参数无别名时使用 restrict 关键字 |

### 2.6 BARR-C 安全编码

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 2.6.1 | | if / for / while / do-while 即使单行也加大括号 |
| 2.6.2 | | 禁用裸 int / short / long，必须用 stdint.h 固定宽度类型 |
| 2.6.3 | | 位操作只对无符号操作数，移位计数 < 操作数位宽 |
| 2.6.4 | | 非 void 返回值必须检查，或显式标注忽略 |

## 3. 内存安全与 Struct 布局

📚 **对应详细规范：** [`memory-safety.md`](./memory-safety.md)

### 3.1 动态内存

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 3.1.1 | | **PID 回调、中断、1kHz 快路径、Wasm 热路径 禁用 malloc/free** |
| 3.1.2 | | 所有结构体静态分配，或通过 FreeRTOS 队列传递 |
| 3.1.3 | | 每次分配都检查 NULL 返回 |
| 3.1.4 | | 每次分配都配对释放，并文档化所有权 |
| 3.1.5 | | 按相反顺序释放（A→B→C 分配，则 free C→B→A） |
| 3.1.6 | | 释放后置空指针（防 use-after-free / double-free） |
| 3.1.7 | | 错误路径使用 goto 标签集中清理已分配资源 |
| 3.1.8 | | 绝不混用不同 allocator 家族（项目统一 allocator） |

### 3.2 禁止 API 黑名单

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 3.2.1 | | 禁用 VLA（变长数组 int a[n]） |
| 3.2.2 | | 禁用 strcpy，使用 snprintf 或 memcpy + 手动补 '\0' |
| 3.2.3 | | 禁用 sprintf，使用 snprintf |
| 3.2.4 | | 禁用 gets |
| 3.2.5 | | 禁用 alloca |
| 3.2.6 | | 禁用 strncpy（不保证 null 终止且效率低） |

### 3.3 缓冲区与栈安全

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 3.3.1 | | 缓冲区连同长度一起传递，拷贝前校验输入长度 ≤ 目标容量 |
| 3.3.2 | | 缓冲区大小定义为宏，无魔法数字 |
| 3.3.3 | | **禁止递归**（或严格有界 + 可证明安全） |
| 3.3.4 | | 大型局部变量评估栈使用，紧张时改堆 |
| 3.3.5 | | FreeRTOS 任务栈按最深调用链 + 余量配置 |
| 3.3.6 | | 使用 uxTaskGetStackHighWaterMark 监控栈使用 |
| 3.3.7 | | 环形缓冲读写指针更新前加内存屏障（多核环境） |

### 3.4 Struct 布局

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 3.4.1 | | DAL/运行时 POD 结构体**自然对齐，禁止 __attribute__((packed)) / #pragma pack** |
| 3.4.2 | | 成员按对齐要求**降序排列**（8B → 4B → 2B → 1B） |
| 3.4.3 | | **配置区（const）与状态区（struct state {}）显式分离** |
| 3.4.4 | | 跨进程/跨 target 数据（网络帧、持久化记录）独立命名定义 |
| 3.4.5 | | **永远不将运行时 POD 结构体直接 memcpy 到 wire/flash** |
| 3.4.6 | | 所有跨边界数据转换通过显式序列化/反序列化函数 |
| 3.4.7 | | 序列化函数处理字节序、版本校验、CRC 完整性校验 |

#### 标准 Struct 布局模板 ✅

`c
typedef struct {
    /* --- 配置区：codegen 初始化后永不修改 --- */
    const uint8_t  pwm_channel;
    const float    min_pulse_ms;
    const float    max_pulse_ms;
    
    /* --- 状态区：运行时可变 --- */
    struct {
        float      current_angle;
        bool       is_enabled;
        uint32_t   last_update_us;
    } state;
} dal_servo_t;
`

## 4. 并发与线程安全

📚 **对应详细规范：** [`concurrency.md`](./concurrency.md)

### 4.1 共享资源保护

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 4.1.1 | | 线程 ↔ 线程：使用 mutex / 信号量 |
| 4.1.2 | | ISR ↔ 线程：使用临界区 / 关中断 |
| 4.1.3 | | 读多写少：使用读写锁（若可用） |
| 4.1.4 | | 简单标志位：使用原子操作 |
| 4.1.5 | | **数据交换优先使用消息队列**（完全避免共享状态） |
| 4.1.6 | | 需要优先级继承时必须用 mutex（不是 binary semaphore） |

### 4.2 临界区规则

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 4.2.1 | | 临界区尽可能短 |
| 4.2.2 | | 临界区内绝不调用阻塞函数 |
| 4.2.3 | | 临界区内绝不分配内存 |
| 4.2.4 | | 文档化为什么需要这个临界区 |

### 4.3 ISR 规则

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 4.3.1 | | **ISR 优先级上限合规**：调 *FromISR API 的中断优先级在允许门槛以下 |
| 4.3.2 | | 高于门槛的 ISR：只读写寄存器 + 释放信号量，绝不调任何 RTOS API |
| 4.3.3 | | **ISR 尽可能短，只做一件事——释放信号量或置 flag** |
| 4.3.4 | | 实活交给任务上下文（工作线程模式） |
| 4.3.5 | | ISR 安全的函数不得调用不可重入函数 |

#### ISR → 信号量 → 工作线程 标准模式 ✅

`text
ISR（最短）→ osSemaphoreRelease / xSemaphoreGiveFromISR（ISR 安全）
              ↓
  高优先级工作线程被唤醒 → 读硬件 → 回调
              ↓
  回调在任务上下文执行 → 可用任意 RTOS / 框架 API
`

### 4.4 volatile / 原子 / 内存序

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 4.4.1 | | **明确区分三者**：volatile ≠ 原子 ≠ 内存序 |
| 4.4.2 | | volatile 只解决编译器优化，不保证原子性或可见性 |
| 4.4.3 | | 单核 ISR 共享的读-改-写操作：volatile + 关中断 / 临界区 |
| 4.4.4 | | 跨核 / 需跨核可见性：使用 _Atomic（带 acquire/release 序）或 portMUX_TYPE spinlock |

### 4.5 单核 vs 多核差异

| 检查项 | 状态 | 单核（Cortex-M） | 多核（ESP32 Xtensa） |
|--------|------|-----------------|---------------------|
| 4.5.1 | | 线程间共享：mutex | mutex |
| 4.5.2 | | ISR ↔ 线程：关中断 / 临界区 | spinlock + 内存屏障 |
| 4.5.3 | | 标志位：volatile 通常足够 | _Atomic 必须 |

### 4.6 Wasm 仿真注意事项

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 4.6.1 | | **Wasm 是单线程，PAL mutex 是假锁** |
| 4.6.2 | | 不依赖 PAL mutex 在仿真里保证跨任务正确性 |
| 4.6.3 | | 真机的并发正确性靠 xtensa target 的真实 OSAL 保证 |

### 4.7 可重入性

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 4.7.1 | | 被多上下文调用的函数可重入：不依赖隐藏的 static / 全局可变状态 |
| 4.7.2 | | 不可重入的函数通过模块 API 串行化访问 |

## 5. 实时性与硬件交互

📚 **对应详细规范：** [`realtime-hardware.md`](./realtime-hardware.md)

### 5.1 RTC / 事件驱动

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 5.1.1 | | 整条 RTC 调用链**非阻塞** |
| 5.1.2 | | 事件处理路径无阻塞调用 |
| 5.1.3 | | 无忙等循环 |
| 5.1.4 | | 事件处理路径不等 mutex |
| 5.1.5 | | 可能阻塞的操作交给内部工作线程 |
| 5.1.6 | | 每个事件处理器有明确的**最坏执行时间（WCET）预算** |
| 5.1.7 | | 超过 WCET 预算时断言失败 |

### 5.2 非阻塞驱动模式

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 5.2.1 | | 驱动内部实现非阻塞：工作线程 + 消息队列 + 回调 |
| 5.2.2 | | 公共 API 入队后立即返回 |
| 5.2.3 | | 周期性轮询留在驱动内部，不对外暴露 poll 接口 |
| 5.2.4 | | 结果/错误通过回调通知应用 |
| 5.2.5 | | 内部细节不出现在头文件 |

### 5.3 DMA 环形缓冲

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 5.3.1 | | DMA Circular 模式：硬件搬运，CPU 不参与 |
| 5.3.2 | | UART Idle-Line 检测支持变长接收 |
| 5.3.3 | | ISR 只释放信号量，不处理数据 |
| 5.3.4 | | 读写索引分离：无锁设计 |
| 5.3.5 | | Cortex-M7 读 DMA 数据前失效缓存行或放在 non-cacheable 区 |
| 5.3.6 | | 错误恢复：abort DMA → 重置环形 → 重启 DMA → 回调通知上层 |

### 5.4 寄存器级验证

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 5.4.1 | | 寄存器地址 / 位域定义正确 |
| 5.4.2 | | 需要时用正确的读-改-写（RMW）序列 |
| 5.4.3 | | 所有硬件寄存器指针用 volatile |
| 5.4.4 | | 外设访问宽度正确（8/16/32-bit） |
| 5.4.5 | | 寄存器访问间有必要延时 |
| 5.4.6 | | 访问前已启用外设时钟 |
| 5.4.7 | | 引脚复用 / GPIO 复用功能已配置 |

### 5.5 看门狗设计

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 5.5.1 | | 每个关键任务 / 状态有自己的超时预算 |
| 5.5.2 | | 推荐分层：IWDG 兜底全局、WWDG 监控关键时序任务 |
| 5.5.3 | | 喂狗放在「任务正常推进的证据点」，不放在无脑定时器里 |
| 5.5.4 | | 复位后读取并记录复位源（RCC CSR / reset reason） |

### 5.6 持久配置 / NVS 加载校验

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 5.6.1 | | 每条配置带版本号 + magic + CRC |
| 5.6.2 | | 加载失败 → 回退安全默认值，绝不带脏值运行 |
| 5.6.3 | | 字段逐一范围 / 类型校验 |
| 5.6.4 | | 关键安全阈值（过流 / 过温）若 NVS 损坏，落到最保守安全值 |
| 5.6.5 | | 配置结构跨 target 持久化用显式 marshal，禁位域 |

### 5.7 双 Target 同源编译

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 5.7.1 | | 跨平台结构体禁用 #pragma pack 与位域 |
| 5.7.2 | | 不用 clang-only / GCC-only 特性 |
| 5.7.3 | | ISR 签名在编译期强制一致 |
| 5.7.4 | | **#ifdef SIMULATION 隔离尽可能收窄**：只旁路最低层物理信号源 |
| 5.7.5 | | 协议解析 + CRC + 错误检测在仿真与真机间共享 |
| 5.7.6 | | Asyncify 栈预算充足：深嵌套考虑栈溢出 |
| 5.7.7 | | Wasm 单线程与 FreeRTOS 抢占多任务语义差异文档化 |

## 6. 静态分发架构

📚 **对应详细规范：** [`static-dispatch/patterns.md`](../embedded-best-practice/references/static-dispatch/patterns.md) + [`static-dispatch/architecture.md`](../embedded-best-practice/references/static-dispatch/architecture.md)

### 6.1 分层架构

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 6.1.1 | | 依赖严格向下：BAL → DAL → PAL → Targets |
| 6.1.2 | | App/BAL（应用层+算法层）只调 DAL 语义 API，不碰 GPIO/I2C |
| 6.1.3 | | DAL 是时序翻译器：硬依赖 PAL 总线/OS API，不含芯片寄存器代码 |
| 6.1.4 | | PAL 只定义契约（HAL + OSAL），无实现 |
| 6.1.5 | | Targets 每平台一份适配实现 |

### 6.2 静态分发铁律

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 6.2.1 | | 器件结构是纯 POD：无函数指针、无 ops、无 vptr、无父类嵌入 |
| 6.2.2 | | 调用是命名式 API 直调：dal_servo_set_angle(&dev, angle) → 直接进函数体 |
| 6.2.3 | | 无 container_of 向下转型：编译期类型已知 |
| 6.2.4 | | 注册靠编译期绑定（codegen 静态全局 / CMake 文件链接） |

### 6.3 四种静态分发形态

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 6.3.1 | | **形态 1 - POD + 命名 API（DAL / 驱动）**：首参传实例指针 |
